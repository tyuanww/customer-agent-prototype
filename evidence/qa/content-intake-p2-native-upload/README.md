## 实际交付

Dashboard 从空候选开始，原生选择标准 XLSX，明确选择整理者与全部实际改稿人，调用真实对象上传、候选接收和解析。阻断错误显示位置与问题总数，完整 XLSX 报告通过认证下载、原子落盘并由 ExcelJS 重新读取；整批更正后接入已有来源确认、合成组织审批、人工质量检查、发布和普通坐席查询/复制。

Main 独占文件路径和原字节、上下文与主体映射、原操作编号和未知提交恢复；renderer 只发送精确的窄意图。权限失效隐藏材料，退出/换人清除会话内文件；上下文变化要求重新确认。停止本机等待不取消服务端解析，晚响应不能替换新状态或释放另一请求。

两个边界方案比较及授权记录见[计划 §0.29](../../../docs/plans/2026-10-03-content-intake-requirements.md#029-faq-原生上传纵向切片2026-10-07)。文件/声明/恢复内聚在上传模块，原生文件模块隐藏对话框、有限读取与原子保存；没有增加 renderer 文件系统能力或任意 HTTP/IPC。

## 审查与修复

使用 `open-code-review-delegate` 确定文件和规则，宿主审阅全部可审增量，并补读被 OCR 排除的测试、文档。`/review` 的原生独立对抗审查覆盖生产代码及调用方，测试/fixture/probe 以 SUMMARY 交给独立审查，原始断言由父审查补齐。未调用外部审核模型；历史外部超时和无效完成标记仍为历史覆盖缺口。

首轮确认并修复两个 P1：

1. 历史/停用贡献人的身份事实截止被误当成当前上传人的授权截止，造成合法声明整批阻断。现在由当前会话/来源权限/管理上下文控制操作资格，贡献人只描述实际参与；保留本人映射、事实版本和分页前后上下文一致性校验。
2. 已打开候选 B 时，刷新旧上传 A 的结果可能替换 B 并清除尚未提交输入。Main 拒绝跨候选交接，UI 在来源/发布输入或质量草稿未提交时禁用历史解析刷新；只读报告不主动清空表单。

两项均保留修前失败和修后通过的回归。最终零修改复审的 `(path,status)` 覆盖清单、原生输出和 gstack 绑定记录保存在本工作树 `.gstack/qa-reports/content-intake-native-upload-20261007/`，随会话交付报告核对；本文件不将外部未执行写成外部通过。
