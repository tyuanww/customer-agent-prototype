## 实际验证

准确命令、输入 SHA-256、日志和运行环境见 [verification.json](verification.json)。本轮保存了修复前失败、修复后通过记录；首次 typecheck 的新测试 mock 返回值错误已修正，原失败仍保留。旧 Dashboard E2E 的过期免责声明断言已按修改前就存在的产品规则修正；一次 Electron evaluate 调试连接异常在同命令复跑时消失，另保留原记录。一次并行 build/test 触发合同生成锁，等待 build 完成后串行重跑 test。报告、解析和发布不能仅以进程退出成功代替验证：Electron 测试实际选择合成文件、走 Main/HTTP/PG、保存 XLSX 并用 ExcelJS 回读，最后由另一名普通坐席查询同一发布并复制。

根 lint/typecheck/test/build、受影响 component/Main 测试、FAQ 原生闭环、旧 Dashboard 相邻原生检查及文档/工作区检查的最终结果以 verification.json 为准。OCR 提交覆盖和工作区覆盖逐项记录在本轮忽略证据目录；原提交不变内容按精确哈希复用，新增代码重新审阅。独立原生审查的测试语料采用 SUMMARY，父审查完整检查相关测试。

证据汇总工具另保留一项元数据失败：历史 capture002 标记为 superseded，但截图输出目录与最终 capture007 不同，工具未把两条命令配对。原始汇总的 fail 不改写；当前输入的必需检查以 capture005/006/007 的实际通过回执逐项核对，不把汇总工具也写成通过。
