2026-10-07，增量基线 `951269e`。本轮分合同、桌面工作流、真实HTTP/PG验证三线独立工作区开发，父线按文件SHA集成。合同草案独立本地提交 `63e7130`，产品继续消费已冻结OpenAPI1.18/schema1.21，没有提前intake1.19。

## 实现与边界

已有候选可在Dashboard查看材料、确认来源、发起/读取/刷新审批、完成人工质量并发布。Main构造候选键、证据版本、基线和原操作编号；renderer只传人工意图。来源/审批重放原POST，发布查询原回执；操作结果与当前候选状态分别保存。审批创建可能半提交，不能因后续错误另造创建编号。

独立宿主用实际登录/资料HTTP模块、PG15和三条合成多行FAQ，前置真实上传/解析只为准备候选；桌面上传UI尚未实现。审批是终端显式推进的合成transport，没有真实飞书、正式factory或新ACL。宿主PG/对象与另起Electron userData分开持有。

## 审查与修复

使用用户指定OCR delegate的preview/rule及宿主审查，并按/review补独立宿主对抗审查；没有调用外部模型，不改写历史外审超时/失败。父审阅所有测试全文；独立reviewer对测试/fixture/support只看名称和接口摘要，该覆盖缩减不隐瞒。

已用失败回归确认并修复：被拒审批无法重新发起、未保存质量输入挡不住工作流、反向表单/质量草稿互锁、首次尚未核验被误报审批服务不可用、连续来源确认不清空已提交输入。CLI另修复独立桌面目录清理所有权与EOF吞掉排队命令。独立审查额外发现初始化期间SIGINT/SIGTERM绕过清理，真实失败probe已确认且清理干净；修复将信号处理放到初始化之前并保留至清理结束，SIGTERM/SIGINT回归均通过。
