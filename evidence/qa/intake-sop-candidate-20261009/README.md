# 首期 SOP 图片解析候选证据

日期：2026-10-09

本轮把用户确认的首期 SOP 口径实现为 `packages/content-intake/src/sop.ts` 的合成候选：

- 六个登记工作表全部纳入，原工作表名称保留为分类。
- 每行收集所有非空文字，按列顺序和单元格换行合并。
- 图片按同一工作表行关联；同一行多张内嵌 PNG/JPEG/GIF 全部提取为受限附件元数据。
- 图片所在行没有文字时整批拒绝，并保留工作表与行号。
- 明确的“版本/版本号”字段优先作为版本；没有时使用原文件 SHA-256。
- 解析结果包含原始图片字节的受限 Base64 候选，尚未写入对象存储或查询目录。

## 验证

```text
pnpm --filter @customer-agent/content-intake test
```

结果：3 个测试文件、101 项通过，退出码 0。新增 `tests/sop.test.ts` 的 4 项合成测试覆盖正常行与同一行多图、版本字段、图片无文字拒绝、未登记工作表拒绝；其中一项还确认外部超链接只保留文字标签，不会被跟随。完整日志：[vitest.log](vitest.log)，SHA-256：`93f732c0ad1417c1aa987ebb8045cd1fbcdd1786c1ee10855b73f34f2a1e11f5`。

## 边界

测试只使用仓内合成工作簿，没有读取或送入产品解析器真实 SOP、客户正文、员工资料、飞书链接或凭据。候选没有接入 `parser-process`、生产 HTTP、数据库、桌面发布或冻结 OpenAPI/schema；它不构成真实资料导入或生产启用证据。原始工作簿此前只在仓外做结构和媒体数量核对。
