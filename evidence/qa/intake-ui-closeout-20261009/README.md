承接 `codex/intake-organization@7660a295841f9d2d840b2c6c529d3004d2a3efc6`，版本保持 0.3.26。用户“按照原需求推进”延续原实施、验证、修复与本地提交授权。本轮只处理[前轮设计审核](../intake-closeout-20261009/design-review.md)的 D1–D5，没有新增业务范围、正式装配或真实资料接入。

## 实际修改

- D1：权限预览和授权行、目录有效时间、同步截止及材料详情统一为本机可读日期，并标出该时刻的 UTC 偏移；提交仍保持原 UTC wire。空值和非法时间明确显示，未改权限期限或判定。
- D2：资料页依次显示核对材料、确认来源、质量检查、确认发布；顶部根据现有 Main 投影提示当前步骤，按钮仅移动焦点和滚动，不发 IPC。提交回执与当前状态继续区分，未知写指向原操作恢复；不保存第二套流程状态。质量区作为现有来源/发布组件的展示槽，候选和检查行的 key、dirty 清理及互斥条件保留。
- D3：确认来源、冻结抽样、提交检查、发布使用已有 primary token；撤销使用 danger token；概览次要入口复用已有按钮样式。
- D4：“打开候选继续审核”改为“查看候选并完成检查”；来源核对和人工质量检查保留，不重新引入组织审批。
- D5：权限预览确认/返回、撤销确认/取消复用现有 8px 工具栏间距。

所有者为 Dashboard renderer，仅本机时间显示抽取一个纯函数。Main/preload/API/DB/角色与正式合同无变更。发布二次确认和服务器门禁仍由原所有者负责。
