# 产品实施仓文档生命周期与项目状态边界

> 本文说明产品仓如何保存产品实现事实，以及它与项目记录仓的关系。它不复制项目当前门禁数字，也不构成 DEV-M0、真实数据接入或上线授权。

## 1. 两个仓库各自回答不同问题

| 问题 | 权威位置 |
| --- | --- |
| 当前项目处于哪一阶段、G0 / Ddev 是否授权、批准范围是什么 | `ai-赋能立项/business-docs/01-客服Agent项目/` 的 `00–06` 真源 |
| 产品 UI、客户端、模块、测试和打包实际做了什么 | 本仓的源码、测试、`DESIGN.md`、`DEVELOPMENT_BRIEF.md` 和架构参考文档 |
| 需求会当时说了什么 | 项目记录仓冻结的 D0 历史快照；不因当前进度变化而回写 |
| 当前业务执行中心和 PRD 视图 | 项目记录仓由生成器从当前真源生成；本仓不把它复制成运行时依赖 |

两个仓库保持独立 Git 历史、工作区和运行时。产品代码、测试通过或 Demo 可运行，不会自动推进项目状态；项目记录仓的状态也不会被产品仓在运行时读取。

## 2. 产品仓内的文档类型

- `PROJECT_CHARTER.md`、`DESIGN.md`、`DEVELOPMENT_BRIEF.md` 和 `docs/reference-*.md` 是产品当前边界、交互和工程知识的稳定文档。
- 源码、测试和构建证据记录“产品实现事实”；它们不能替代批准记录、G0 / Ddev 或生产验收证据。
- `CHANGELOG.md`、`TODOS.md` 和带日期的审查/验证材料保留历史变化；历史材料可以追加勘误，但不覆盖已发生的记录。
- 当前桌面默认仍是 `DEMO · MOCK AUTH · SYNTHETIC DATA`；未设置 loopback 时走编译期 fixture（NO BACKEND 仅指该默认 profile）。显式 loopback 接入 profile 已接线 D1–D5 合成 adapter，仍不是真实后端、正式运行或上线。合成 fixture、Dashboard manifest 和本地运行结果不得写成真实接入、上线或客户验证。

当前一期任务统一从[执行清单](plans/2026-09-06-execution-goal.md)恢复。D0–D5 合成桌面工程已合并；该阶段设计真源仍是 [2026-09-09 准备](plans/2026-09-09-desktop-integration-preparation.md)。Windows 安装包与实机以 [2026-09-10 DRAFT](plans/2026-09-10-windows-package-and-device-verification.md) 为计划入口，状态 DRAFT，不得当作已批准开工。章程和 README 只链接入口；带日期的计划保存当时的批准、设计和证据，页头明确历史属性。功能说明随功能交付；merge SHA / CI 由 GitHub 和既有交付证据记录，不为同步每个 SHA 循环新增文档 PR。

## 3. 修改与交接规则

1. 项目范围、阶段门或授权发生变化时，先更新项目记录仓的当前真源；本仓只在获得明确的实施输入后调整产品计划或代码。
2. 产品实现变化留在本仓，并用测试/构建命令形成可追溯证据；需要回填时向项目记录仓提交摘要和证据引用，不复制另一份动态状态。
3. 产品仓文档不保存真实客户原文、飞书凭证、token、内部批准原话或未脱敏链接；正式 adapter、OAuth、数据库和线上 API 必须受当前获批里程碑及剩余数据 / 安全门约束，Ddev 开工不得被扩大解释为真实接入。
4. 本地 Demo 不使用文件 watcher、跨仓运行时读取或飞书实时双向同步。需要查看项目动态时，人工打开项目记录仓生成的当前视图并刷新。
5. 业务原表与项目主源副本分开留存；项目使用已确认的四域汇总工作簿，来源比较及表头补齐结论由项目记录仓的带日期证据保存。显示内容一致不等于可装包版本已冻结，更不替代权限、有效期、manifest 锚点和正式运行批准。不得为消除已确认的表头补齐而覆盖主源，也不把话术正文或内部链接写入本仓。

## 4. Menokin 单一试点的分阶段含义

Menokin 是当前唯一客服试点。本仓已有的 UI Demo 是同一试点的合成实现基线，不是另一个项目，也不与项目记录仓的项目进度 HTML 或 PlantUML 浏览器混用。`DEC-054 / DEC-055` 将合成 profile 登记为 `PILOT-S0 · SYNTHETIC`；截至 2026-08-31，项目记录仓又签发 `DEC-DDEV-01=PASS`，用户随后明确授权产品仓开工。该状态快照只用于解释本仓为何进入 `DEV-M0`；后续门禁变化仍以项目记录仓动态真源为准。

| 阶段 | 当前可做 | 仍不可做 |
| --- | --- | --- |
| `PILOT-S0 · SYNTHETIC` | 本地 UI、交互、纯状态模型、编译期合成 fixture、测试、构建、开发诊断、非正式 Windows feasibility smoke | 真实数据、飞书运行接入、正式 API / worker / migration、凭证、付费、遥测、自动发送、部署 |
| 正式 `DEV-M0` | **产品实施已完成**：W0～W6 已合并；clean-checkout CI、Windows 可行性 smoke 和非部署型正式服务候选产物隔离证据已落入 `main@44b863d` | 真实数据、飞书运行接入、Pilot、付费、遥测、自动发送、部署、发布；合同运行时仍未激活 |

S0 的代码和测试可以动态推进；已经完成并冻结的历史决定只保留，不反复改写。阶段证据分账是为了防止误报，不代表拆成两个客服项目。项目记录仓的当前 HTML 继续由 `00–06` Markdown 真源生成；本仓不复制其动态计数，也不建立跨仓 watcher 或运行时同步。

项目记录仓的完整规则见同目录的 `文档生命周期与动态视图规则.md`。该引用是人工协作入口，不是产品运行时依赖。
