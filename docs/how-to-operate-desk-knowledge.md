# 如何记下一条人设知识

在 `contentIntake: "faq-v2"` 的工作台里，给当前人设写一条问答，或导入 CSV。导入后的条目是未生效，坐席还搜不到。查询浮层不读这张表。

字段和通道见[人设知识库](reference-desk-knowledge.md)。为什么不把它接进查询目录，见[为什么知识库不读查询目录](explanation-desk-knowledge.md)。

## 前提

- 桌面用显式 FAQ 合成 profile 启动。侧栏「知识库」就是导航 id `content`。
- 运营是已登录的 `coach` 或 `owner`。坐席是 `agent`，只能切换人设和记下隐性知识。
- 知识写在本机 `userData/desk-knowledge.json`。这不是服务器上的 FAQ 候选，也不是旧工作台的整库替换。

## 步骤

1. 打开工作台，侧栏点 **知识库**。标题是「知识库」，旁边的数字是当前人设的条数。

2. 在标题下点 **全店**、**售前客服** 或 **售后客服**。下面一行写「坐席会收到 N 条。全店生效的知识会一起送到这个人设。」

3. 运营点 **写下一条**。填写问题和答案。分类保持默认，或改成商品介绍、搭配建议、售前咨询、售后服务、自定分类。有效期选长期生效、不生效或定时生效。定时才填开始和结束，用 ISO 时间。点 **保存**。

4. 要批量写入时，仍在这一层底部选 CSV。表头用「问题 / 标准话术」。分类可写售前、售后、产品、活动。不要选 xlsx。

5. 卡片上悬停后，可以把一条改为长期生效或不生效，或删除。删除要在确认层点 **确认删除**。解析失败的卡片才有 **重试**。

6. 坐席只看已投递的卡片。页面上没有「保存」。隐性知识记在卡片下面，交给知识库之后仍是未生效。

## 怎样确认

- 保存一条长期生效的全店知识后，文案出现「生效中」，而且「坐席会收到」的条数增加。
- 导入成功时看到「已导入 N 条，状态是未生效。」切到对应人设，这条不是生效中，条数不因它增加。
- 坐席账号做保存、导入或删除时，看到「当前账号暂无使用权限，可向主账号发起权限申请。」
- 查询窗口的结果仍来自原来的目录，不出现刚才只存在于知识库、尚未进入发布目录的句子。

## 失败时

- 「请先在查询窗口登录。」：当前没有坐席或运营会话。
- 「当前运行模式没有接上知识库。」：不是 `faq-v2`，主进程没有登记 desk 通道。
- 「问题需要 2 到 80 个字。」或「请填写答案。」：问答不完整。
- 「文件超过限制。请选择不大于 10 MiB 的 CSV。」：CSV 太大。
- 「没有可以导入的问答。问题需要 2 到 80 个字。」：每一行都被跳过。
- 「知识已更新，但没能写入本机。」：内存已改，`desk-knowledge.json` 没写成。
- 「本机知识库读不出来，已从空库开始。」：文件损坏。下次成功写入会覆盖这份空库，原文件内容不再保留。
