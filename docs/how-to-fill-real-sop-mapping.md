# 真实六表映射填写说明

模板是 [sop-real-six-sheet-mapping.template.json](./sop-real-six-sheet-mapping.template.json)。它已经填好来源路径、来源 SHA-256、六张表的行列数和图片数。这些技术事实不需要人工改动。

模板固定带有 `mappingState: "candidate"`、`mappingStatus: "needs-business-confirmation"` 和 `publishable: false`。这三个字段是机器可读的失败关闭标记。候选编号和入口词设计见 [真实六表业务身份候选设计](./reference-sop-business-identity-candidates.md)，候选设计不能代替业务确认。`mappingStatus` 必须与校验结果一致，不能手工改成准备状态来绕过缺项。

真实工作簿没有“条目编码”表头，不能把行号、标题或图片顺序直接当成业务身份。业务方每次只确认当前缺失的一项业务事实，AI 再整理成以下声明，不要求业务方填写 JSON。每个声明都用对象表示：

```json
{ "value": "业务确认内容", "evidence": "workbook:过敏流程SOP#row:12-18; review:业务确认记录" }
```

`evidence` 必须能让复核人回到原工作簿和业务确认记录。行号只做定位证据，不能单独充当稳定编号。

业务决定应引用可审阅的记录文件，例如 [2026-10-31 SOP 业务决定记录](./reviews/2026-10-31-sop-business-decisions.md)。只写“已确认”或聊天中的临时标签不足以作为正式发布证据。
`待业务确认`、`pending`、`TBD` 和 `TODO` 等占位值会被校验器拒绝，不能用来凑齐完整映射。

## 必填字段

| 字段 | 需要确认的内容 | 填写边界 |
| --- | --- | --- |
| `stableBusinessIds` | 稳定业务编号及其对应对象 | 编号在插入行、调整排版后仍保持不变；无法确认时不要用行号代替 |
| `entryTerms` | 场景入口和坐席识别词 | 只写业务认可的触发词；不能从正文自动猜测 |
| `branchTargets` | 判断结果对应的目标任务或结束节点 | 每个分支要能指向一个稳定任务；没有分支时写明确的终点声明 |
| `unableToDeterminePaths` | 信息不足时的处理路径 | 写明业务已确认的后续动作，不预设转人工或结束。过敏流程使用已确认的流程内补充确认 |
| `knowledgeOwnership` | 知识内容的归属对象和阅读对象 | 区分坐席可读与主管可读，不能把权限当成发布结果 |
| `resourceOwnership` | 资源的业务所有者和适用范围 | 资源可以是内部资料或外部资源，需说明使用边界 |
| `imageOwnership` | 每张图片绑定的任务、知识或对客话术 | 同时确认图片用途、阅读对象和稳定资源身份；不能只写“见图片” |
| `applicability` | 适用的品牌、商品、店铺或场景范围 | 使用业务已有的稳定范围标识，不写自由猜测的范围 |
| `visibility` | 可见对象 | 明确坐席、主管或客户；与 `knowledgeOwnership`、`imageOwnership` 的对象保持一致 |
| `effectiveInterval` | 生效时间、失效时间和依据 | 时间必须使用 UTC ISO-8601；没有失效时间填 `null`，但仍需证据 |

## 六张表的确认顺序

先确认流程表，再确认规则和资源表。建议顺序如下：

1. `过敏流程SOP`：沿用专业坐席判断、信息不足时流程内补充确认、不转人工的[既有决定](./reviews/2026-10-31-sop-business-decisions.md)。先确认一个结果分支的目标步骤和原表行区段，再补其余映射。
2. `长痘痘SOP`：确认入口和步骤边界，补齐信息不足时的后续动作和结束条件，不预设处理路径。
3. `少错破SOP`：确认每个编号是否是稳定业务编号，不能把现有数字默认当作正式编号。
4. `品质售后SOP`：逐项确认图片归属、坐席与主管可见性，以及补偿或退货等需要人工判断的权限边界。
5. `税收相关规则`：确认规则适用范围、生效区间和无法判断时的升级路径。
6. `品牌对接资源汇总`：确认每个资源的所有者、可见对象、适用范围和图片用途；资源表不能自动变成流程节点。

## 逐项确认业务事实

当前只回答[过敏流程审阅卡的下一项业务输入](./reviews/2026-10-31-sop-allergy-mapping-review.md#下一项业务输入)。已确认的坐席判断和补充确认边界不再重复询问。

上表是完整映射的字段说明，不是一次需要填写的问卷。每次答复由 AI 整理为候选声明和确认记录，再提出下一项缺失事实。一个分支的答复不代表整表已审核，也不代表入口词、权限、有效期或其他分支已获批准。

模板检查结果必须达到 `ready-for-graph-preparation`。在此之前不会生成部分图，也不会接入 API、PostgreSQL、Main 或 Query。
