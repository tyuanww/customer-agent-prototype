# 2026-10-24 前端设计结论

状态：设计稿，未经产品批准。本文定的是画面、文案和页面去留。它改写 DESIGN.md 的对应段落，不改授权判断的含义，不放宽账号唯一约束。

## 0. 先定的总方向

**坐席的查询保持现在这样，只改工作台和登录。**

理由：坐席每天用的狐狸、查询条、三条话术和复制已经稳定，现有文案也守住了「复制只表示已复制」。这一轮最痛的是另外两类人：主管给不了权，管理员开不了能登录的账号。把力气放在那里。查询只改两处文字（见第 4、9 项），不改画面结构、不改尺寸、不改动效。

**外观统一成一句话：工作台和登录用同一套 antd 外观，浅底实色，紫色只做主按钮和选中。**

- 工作台和登录窗用 antd 组件，主色 `#8B5CF6`（现有品牌紫），圆角 8，浅色背景实色白，不用玻璃。
- 淡紫只出现在两处：主按钮，侧栏选中行。不铺满页面，不做渐变。
- 查询条和狐狸继续用现有的玻璃外观，不跟着换。它是桌面上的输入工具，不是后台页面。
- DESIGN.md 里登录窗「复用查询胶囊玻璃」的规定作废。登录窗是一个普通系统窗口，长得像工作台的一页，不像查询条。

**使用者三种：**

- 坐席：每天查话术。打开狐狸，不常打开工作台。
- 主管：给自己组里的人开通能力。主要用「权限」页。
- 管理员：管账号、把飞书和账号接上。主要用「账号」页。

文中「主管」指能授权的人，对应现有天花板里能分配权限的三类角色；「管理员」指能管账号的人。目前这两种能力在系统里是同一批人（见 PR 107 的复核结论），本文按人做的事分页，不要求系统先把它们拆开。

## 1. 登录

**结论**：登录窗保留两个选项「飞书」「账号」，默认停在飞书。外观换成工作台同款：白底、实色、紫色主按钮。标题栏保持系统原生，标题「登录」。不内嵌飞书网页。

**谁在用**：所有人。坐席第一次打开查询条点「登录」，或者打开工作台时还没登录。

**画面顺序**

1. 窗口打开。最上面一行分段选择：「飞书」｜「账号」。默认选中飞书。
2. 选飞书：一句「将用浏览器打开飞书登录。」，下面一个紫色主按钮「飞书登录」，旁边一个次按钮「取消」。
3. 点「飞书登录」后，按钮变成转圈，文字「正在打开浏览器…」。浏览器打开后，窗口显示「请在浏览器里完成授权，完成后这里会自动继续。」和一个「取消」。
4. 选账号：两个输入框「登录名」「密码」，主按钮「登录」。下面一行小字「没有账号或忘记密码？请联系管理员。」
5. 成功：窗口自己关上，回到刚才要做的事（查询条或工作台）。

**关键文案**：

- 飞书：「将用浏览器打开飞书登录。」
- 账号：「使用管理员给你的登录名和密码。」
- 账号底部：「没有账号或忘记密码？请联系管理员。」

**做不到时**：

| 情况 | 看到的句子 | 下一步 |
| --- | --- | --- |
| 登录名或密码错 | 「登录名或密码不正确。」 | 输入框保留登录名，密码清空，光标回到密码框 |
| 账号被停用 | 「这个账号已停用，请联系管理员。」 | 不给重试按钮 |
| 浏览器打不开 | 「没能打开浏览器。」 + 「重试」 | 点重试再开一次 |
| 浏览器里没点授权就回来了 | 「还没收到飞书授权。」 + 「重新打开浏览器」「取消」 | |
| 服务连不上 | 「登录服务暂时连不上。」 + 「重试」 | |

「账号已停用」和「密码不对」要分开说。现在两者都显示「账号或密码不正确」，被停用的人会反复试密码。这一条需要服务端在拒绝时多给一个原因（见第 4 项的字段清单），在那之前保持现在的合并文案，不要在前端猜。

## 2. 把一个人的飞书和账号接上

**结论**：放在工作台新的「账号」页里，只有管理员能看到。做法是管理员先选一个已有账号，再填这个人的飞书，系统等这个人下次用飞书登录时把两边认成同一个人。这一屏现在不存在，本文只定画面，不定数据怎么存。

**为什么要有这一屏**：同一个真人如果先有管理员开的账号，后来又用飞书登录，系统会把飞书那次当成另一个人。他在账号下拿到的权限，飞书登录时都没有；主管看权限页会看到两个同名的人。

**谁来做**：管理员。不是主管，也不是本人。

**在哪一页做**：工作台左侧「账号」页 → 账号列表 → 某一行右侧「接上飞书」。

**画面顺序**

1. 管理员在「账号」页的列表里找到这个人（姓名、登录名、岗位、状态、飞书）。「飞书」一列显示「未接上」。
2. 点这一行的「接上飞书」，右侧弹出一个面板，标题「把飞书接到 张三（zhangsan）」。
3. 面板里一句说明：「接上之后，张三用飞书或账号登录，都是同一个人，权限也是同一份。」
4. 一个输入框「飞书里的名字或邮箱」。管理员输入后，下方列出匹配的飞书成员（来自已经登录过的飞书记录）。没有匹配时显示「这个人还没用飞书登录过。可以先让他登录一次，再回来接上。」
5. 选中一个飞书成员后，面板显示对照：左边「账号：张三 / zhangsan / 客服」，右边「飞书：张三 / 售后一组」。
6. 主按钮「确认接上」。点击后先弹确认：「接上之后不能自己拆开。确定把这两个认成同一个人吗？」，按钮「确认接上」「取消」。
7. 成功：列表这一行「飞书」一列变成「已接上」，面板关闭，顶部轻提示「已接上。」。

**接上之前，这个人用飞书登录看到什么**：

他能登录，但权限按飞书那一侧算。工作台顶部出现一条横幅：「你用飞书登录的身份，还没和你的账号接上，看到的权限可能不全。请联系管理员。」查询条不显示这条，只在会话芯片的姓名后面多一个小圆点，鼠标停上去显示同一句。

**做不到时**：

| 情况 | 看到的句子 |
| --- | --- |
| 这个飞书已经接在别人身上 | 「这个飞书已经接在 李四 身上。一个飞书只能接一个人。」 |
| 账号已停用 | 「账号已停用，先启用再接上。」 |
| 请求失败 | 「没有接上。」+「重试」 |

**明确不做**：不提供「拆开」按钮。拆开会让历史授权说不清是谁的，需要另外评审。也不在这一屏改岗位或授权。

## 3. 权限页

**结论**：权限页只做一件事：给某个人、在某个店、开通某一项能力，或者收回。先看清楚再确认。收回后历史保留，不能恢复成原样；要再用，就重新开通一条新的。

**谁在用**：主管。

**画面顺序**

1. 打开「权限」页。上面一行筛选：「店铺」下拉，「人员」搜索框。下面一张表，列是：姓名、岗位、店铺、能力、开通人、开通时间、到期、状态、操作。
2. 右上角紫色主按钮「开通能力」。
3. 点「开通能力」，右侧面板分三步，一屏放下：
   - 选人：搜索框，输入名字，列表里勾一个或几个人。
   - 选店：勾一个或几个店。
   - 选能力：勾选项，每项后面有一句人话：
     - 查话术：「能在查询条里查到这个店的话术。」
     - 上传资料：「能上传这个店的话术表。」
     - 确认来源：「能确认上传的表来自哪里。」
     - 发布：「能把检查好的话术发给坐席。」
     - 回退：「能把这个店的话术退回上一版。」
   - 到期：默认「不设到期」，可选日期。
4. 下面一个次按钮「先看一下」。点了之后面板下半部分出现预览：「将给 张三、李四 开通：Menokin 店的查话术、发布。共 4 条。」对每一条再标出「新增」或「已有，不变」。
5. 预览里有不能开的，单独列出：「李四的发布：你没有给别人开通发布的权力。」这一条前面是灰色，不会被提交。
6. 主按钮「确认开通」，只在预览之后可点。成功后面板关闭，表格里新增的行高亮 2 秒，顶部轻提示「已开通 3 条。」。
7. 收回：每一行右侧「收回」（红色文字按钮）。点了弹确认：「收回 张三 在 Menokin 店的发布能力。收回之后不能撤销，需要再用要重新开通。」，需要填一句原因，按钮「确认收回」（红）「取消」。
8. 收回后这一行状态变成「已收回」，灰色，保留在表里。表格默认只看「生效中」，顶部有一个切换「显示已收回和已到期」。

**关键文案**：

- 收回确认：「收回之后不能撤销，需要再用要重新开通。」
- 预览说明：「这一步不会保存。」

**做不到时**：

| 情况 | 看到的句子 |
| --- | --- |
| 打开权限页的人没有授权的权力 | 页面留着，表格只读，「开通能力」按钮不出现。表格上方一行：「你可以查看本组的权限，但不能开通或收回。需要调整请联系你的经理。」 |
| 预览后有人在别处改了 | 「刚才的预览已经过期，请重新看一下。」，「确认开通」变灰，只剩「先看一下」 |
| 提交时网络断了，不知道成没成 | 「不确定是否已开通。请先刷新列表看一下，不要重复开通。」+「刷新列表」。不给「重试提交」 |
| 普通失败 | 「没有开通。」+「重试」 |

「不确定是否成功」时不给重试按钮，这是故意的：重复提交可能开出两条。

## 4. 没权限

**结论**：工作台和页面都留着，按钮不藏，写明原因和找谁。只有一种例外：「账号」页和「权限」页对普通坐席整页不出现在侧栏，因为坐席根本不需要知道有这两页。

规则：

- 看不到的入口：坐席看不到「权限」「账号」两页。
- 看得到但做不了的：留着，按钮变灰，旁边一句原因和找谁。
- 找谁：写角色，不写具体人名（人名会过时）。「客服主管」「你的经理」「管理员」三种。

**三件事分别怎么说**

| 做不到的事 | 谁会碰到 | 看到的句子 | 去找谁 |
| --- | --- | --- | --- |
| 打开工作台 | 只有查话术能力的坐席 | 工作台照常打开，只显示「话术库」和「SOP」两页，概览位置显示：「你现在可以查话术。需要看数据或管内容，请联系客服主管。」 | 客服主管 |
| 授权 | 打开权限页但不能开通的人 | 「你可以查看本组的权限，但不能开通或收回。需要调整请联系你的经理。」 | 你的经理 |
| 上传资料 | 在资料页没有上传能力的人 | 上传区域变灰，区域内一句：「你还不能上传这个店的资料。请联系客服主管为你开通「上传资料」。」 | 客服主管 |

**和现在的差别**：现在所有拒绝都是同一句「没有权限，请找人开通。」，不说缺哪一项，不说找谁。侧栏上权限页在不在，看的是程序有没有装上权限功能，不看这个人有没有权。改成按人的实际能力决定画面。

**需要服务端多给的字段**（只列含义，不改合同）：

1. 这个人现在能做哪几件事：查话术、上传、确认来源、发布、回退、开通别人、管账号，各一个是或否。
2. 某件事做不了的原因：没开通、已收回、已到期、身份没确认、这个店没有内容。
3. 该去找的角色：客服主管、经理、管理员。
4. 登录被拒的原因：密码不对、账号已停用（第 1 项用）。
5. 飞书和账号是否已接上（第 2 项用）。

在这些字段来之前，前端只能显示现在那一句通用文案。不要在前端根据职务表自己推断「该找谁」。

## 5. 新人进来的前几分钟

| 人 | 看到的第一句 | 下一步 |
| --- | --- | --- |
| 飞书新人（职务已配置） | 查询条：「已登录。可以开始查话术了。」 | 直接输入问题 |
| 飞书新人（职务没配置） | 查询条：「已登录，但还没有为你开通查话术。请联系客服主管。」 | 查询按钮变灰，输入框还能打字 |
| 账号新人 | 登录成功后查询条：「已登录。可以开始查话术了。」 | 直接输入问题。第一次登录不强制改密码（现有流程没有这一步，不新增） |
| 刚被开通新能力 | 工作台顶部轻提示：「你有新的能力：Menokin 店的发布。」只出现一次 | 对应按钮直接可用，不用重新登录 |
| 被收回 | 正在做的事被打断时：「你在 Menokin 店的发布能力已被收回。」查询条里已有的结果被撤掉，显示「你在这个店的查询能力已被收回，请联系客服主管。」 | 不提供重试 |
| 资格过期（5 分钟身份核验没续上） | 「登录状态需要确认，请重新登录。」+「重新登录」 | 点了打开登录窗。不要写「资格已到期」这种内部词 |

「资格过期」现在写的是「读取资格已到期。请刷新权限列表。」坐席和主管都读不懂「资格」。统一改成「登录状态需要确认」。

## 6. 工作台左侧有哪些页

**结论**：七页，按每天打开的频率排。

1. **概览** — 主管看
2. **话术库** — 所有人看，只读
3. **SOP** — 所有人看，只读
4. **知识库** — 主管和运营维护
5. **资料** — 上传话术表、确认来源、发布、回退
6. **权限** — 主管
7. **账号** — 后续。本期不做这一页。坐席的新建、重置、停用仍在权限页。

**去留建议**（删页等操作者确认，本文不删代码）：

| 现在的页 | 建议 | 理由 |
| --- | --- | --- |
| 管理概览 | 留，改名「概览」 | |
| 话术库 | 留 | 已经是只读目录，坐席和主管都要 |
| SOP | 留 | 按要求先留 |
| 知识库 | 留 | |
| 内容管理（publish） | 并入「资料」 | 和资料管理做的是同一件事的前后两段，拆两页让人找不到发布在哪 |
| 资料管理（materials） | 留，改名「资料」 | |
| 权限 | 留，只放授权 | |
| 系统同步 / 公告 | 去掉这一页 | 它显示的「当前发布版本、条数」放到「话术库」顶部一行；软件更新还没接上，不单独占一页 |
| 旧 profile 的话术库、公告、内容 | 去掉 | 新 profile 已有对应页 |
| （新增）账号 | 后续，本期坐席管理仍在权限页 | 第 2 项、坐席的新建、重置、停用仍从权限页操作 |

**同一个名字只指一件事**：现在 `content` 这个位置在旧版叫「内容管理」，新版叫「知识库」。新方案里「知识库」就是知识库，「资料」就是上传发布，不再复用。

**侧栏外观**：宽度固定 220，可以收起成只剩图标。不再提供拖动改宽度。DESIGN.md 里那段拖动像素规则作废，理由：没有使用者提出要调宽度，那段规则的维护成本远大于价值。

## 7. 概览

**结论**：概览只给主管看，只放真实数字。四件事按「先处理、再判断」排。

**谁在用**：主管，每天早上看一眼。

**画面顺序**（从上到下）

1. 顶部一行：时间范围（近 7 天 / 近 30 天 / 自选）。数字只算当前登录者最近读到的记录，不是全店。
2. **待办**（第一块，因为它要人动手）：列表，每行四列：问题、话术、处理人、状态。没有待办时：「现在没有待办。」
3. **不准的话术**：坐席点了「话术不准」的那些话术，按被点次数排。每行：话术标题、被点次数、最近一次时间、「去处理」。没有时：「这段时间没有人报告话术不准。」
4. **没查到的问题**：坐席查了但三条都没给出的问题，按出现次数排。问题原文按记录规则显示，被脱敏的显示「已脱敏」。没有时：「这段时间所有查询都有结果。」
5. **改过之后有没有变好**：只对「已处理」的待办显示。每行：话术标题、处理前一段时间的不准次数、处理后同样长时间的不准次数。处理后的时间还不够长时，写「处理后时间还短，先不比较。」

**每个数字是什么**（人话，公式留给分析层的卡）：

- 查询次数：坐席在查询条点了查询的次数。
- 没查到：查询后一条话术都没给出的次数。
- 被复制：坐席点了复制的次数。只表示复制了，不表示发出去了。
- 不准次数：坐席点了「话术不准」的次数。

**不放的东西**：命中率。在口径没定之前，「命中率」这个词不出现在概览上。只放上面四个次数。也不放「较上期 ↑ 8%」这类对比。

**没有数字时**：

- 没登录：「请先登录。」
- 数据还没接上：一句何时会有数据，例如「坐席查询后会出现」（不写「未接入」，那个词操作者读不懂）
- 读取失败：「没读到。」+「重试」
- 接上了但这段时间是零：显示 0，不显示空。0 是真实数字。

**预览样例**：现在概览在本地预览模式下会出现「较上期 ↑ 8%」等样例。这些只能出现在开发预览里，正式画面不能出现，包括失败时的兜底。

## 8. 等待、成功、失败、复制、危险操作

| 场景 | 什么时候出现 | 画面 |
| --- | --- | --- |
| 等待（短） | 按钮点下后不到 1 秒的动作 | 按钮本身转圈，文字不变，按钮变灰防止连点 |
| 等待（列表首次加载） | 打开页面，数据还没回来 | 表格位置显示骨架（灰色条），不显示「加载中」文字。超过 8 秒加一句「还在读取…」 |
| 等待（长任务） | 上传话术表、发布 | 分步显示：「正在读取文件」→「正在检查」→「正在发布」，每步前面一个勾或转圈。可以离开页面，回来还在 |
| 成功（轻） | 保存、开通、收回、接上 | 窗口顶部轻提示，2 秒消失：「已开通 3 条。」「已收回。」「已接上。」 |
| 成功（重） | 发布 | 页面里留一块结果：「已发布第 12 版。坐席下次查询就能用。」+「去话术库看看」 |
| 失败（能重试） | 网络断了、服务超时 | 原位置一句「没有保存。」+「重试」。输入不清空 |
| 失败（不确定） | 提交后没收到回应 | 「不确定是否已保存。请先刷新看一下，不要重复提交。」+「刷新」。不给重试 |
| 失败（不能重试） | 输入不合规、没有权力 | 原位置一句具体原因，不给重试 |
| 复制 | 坐席点话术卡的「复制」 | 按钮文字变成「已复制」约 0.9 秒，然后查询条收起。只写「已复制」 |
| 危险操作 | 收回能力、停用账号、回退版本、接上飞书 | 先弹确认框。标题说清楚做什么，正文说清楚能不能撤销。确认按钮红色（接上飞书用紫色，因为它不是删除），默认焦点在「取消」 |

**复制的规矩**：任何地方都不能出现「已发送」「已采纳」「已解决」「已回复」。概览里的「被复制」后面要跟一句「只表示复制了」，鼠标停上去也能看到。

## 9. 坐席会不会看到「正在被记录」

**结论**：会。第一次登录后查询前弹一次告知，坐席选「同意」或「不同意」。不同意也能照常查话术，只是不记录。之后可以在查询条的菜单里改。

**记录范围**：只有四样——查了什么问题、有没有查到、复制了哪一条、点了话术不准。不记录顾客聊天，不记录坐席最后发了什么。

**画面顺序**

1. 坐席第一次登录成功，点查询前，查询条下方展开一块告知（不另开窗口）。
2. 标题：「使用记录说明」
3. 正文：
   > 为了改进话术，本软件会记录你在查询条里做的四件事：你查的问题、有没有查到、你复制了哪一条、你点了「话术不准」。
   >
   > 不会记录你和顾客的聊天，也不会记录你最后发给顾客的内容。
   >
   > 问题里的手机号和身份证号会被替换掉。
   >
   > 你可以选择不同意。不同意也能照常查话术，只是这些不会被记录。以后可以在菜单里改。
4. 两个按钮：「同意」（紫色主按钮）、「不同意」（次按钮）。阅读不算同意，必须点。
5. 选完后告知收起，正常查询。
6. 以后想改：查询条右侧的菜单（现在打开工作台的那个图标旁边）里一项「使用记录：已同意 / 未同意」。点了重新显示同一块告知，可以重新选。

**撤回之后**：从撤回那一刻起不再记录。已经记下的内容不会因为撤回立即删除（现有系统按保留期自动过期）。这一点要在告知里写出来，不能让坐席以为撤回就删了：

> 撤回后不再记录。之前已记录的内容会按保留期自动删除。

**不写的话**：不写「符合个人信息保护法」「符合平台规则」。淘宝、抖音的数据规则和法律条款没有经过法务核实，界面上不能暗示已经合规。

**和现在的差别**：现在告知标题是「试点采集告知」，正文没有写清楚不记录什么，也没有写撤回入口。另外，2026-10-15 曾决定不做采集，2026-10-24 操作者重新放开 L0；本项按 10-24 的决定设计。姓名、地址目前不脱敏，告知里只写已经做到的「手机号和身份证号」，不夸大。

## 关于检索放在哪（E4）

查询仍在坐席电脑上算，不改成等服务器。坐席看到的画面和速度不变。以后真的移到服务器，查询条的画面也不需要变，只是「正在查」可能多等一会儿，届时再定等待文案。
