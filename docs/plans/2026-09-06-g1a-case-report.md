## 问题与边界选择

G1a 聚合报告足以核对总分和分层阈值，但不能追溯每题实际候选。治理 DEC-SEARCH-01 的 RUN 证据要求包含逐题结果；现有报告器已保留分层，仍缺完整逐题向量。

比较两个边界：让仓外报告器读取答案并根据总数重建结果，会把推断写成观察事实，也扩大真实输入接触面；由实际评测循环保留观察到的候选身份，仓外仅投影允许字段，可以直接复用判定所有者。采用后一种方案。

## 所有者与合同

`apps/api/tests/support/g1a-e0/evaluate.ts` 继续唯一拥有评测过程和判定。为现有内部报告增加 `case_results`，按冻结输入顺序逐题保留：case/stratum ID、预冻结搜索与下游动作、hit/no_hit/backend_error、预期候选与禁止候选是否出现、搜索动作判定、完整候选四元组与 rank、每个候选的 provenance 检查及逐题失败码。

这是内部报告的附加字段；既有分数、阈值、失败码、报告状态和搜索实现不变。预期动作带 `expected_` 前缀，不能表示已执行；`downstream_action_evaluation` 继续为 NOT_EVALUATED。

后端抛出异常和返回错误归一到 backend_error，不把它们记成正常无命中。记录只使用明确列出的元数据，不复制候选正文。成功搜索动作与候选来源正确性分开保留；命中预期 ID 不能覆盖 provenance 失败。

仓外新版本报告器验证 50 条唯一用例、20/12/18 分母、Top3 排序、计数/分层/失败码一致性，并将 case/script/release/stratum ID 转为包绑定哈希引用。遇到缺项、正文或矛盾字段失败关闭；旧操作器及既有真实报告保留。新报告器只适用于包含逐题字段的报告，不能从旧聚合中恢复已经丢弃的信息。
