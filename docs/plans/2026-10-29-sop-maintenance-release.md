## 固定产品和内容边界

- 面向新人，同时支持上岗学习与接待执行。手册浏览不创建或改变活动执行会话。
- 普通搜索保持原样。SOP 命中只产生候选入口，由坐席主动选择。多候选不能自动启动。
- 同一 Query 窗口一次只执行一个客户的一条流程。返回搜索、主动收起保留进度；结束、重启或替换流程需明确确认。
- 当前任务、必要材料和判断条件默认可见。话术正文默认折叠，标题、适用条件及复制按钮可见。展开与复制互不依赖。
- 多条话术分别复制。快捷键只复制唯一可用或明确选中的一条。未确认变量不复制；复制不推进、不发送、不代表已处理。
- 普通任务主动下一步；判断任务选择分支；必须支持资料不足或无法判断的后续动作。
- 历史浏览不推进。修改历史选择需确认并清除受影响的后续选择、材料确认和复制目标。剪贴板已有内容无法撤回，不暗示已撤回。
- 等待客户、等待内部协助是当前流程状态，不扩展成多客户工单系统。终点只说明流程结束，不代表客户问题已解决。
- 坐席操作指引、主管专属资料、对客可复制内容分别授权。不得把所有「内部」内容一律隐藏给新人，也不得向新人放开主管内容。
- 流程绑定内容版本；普通发布不静默替换活动流程。权限中断时停止查看、推进和复制，清除无权持有的正文，仅保留必要的进程内恢复信息；权限恢复后，在原内容仍有效且当前权限重新核验通过时继续原流程。会话自动过期后允许同一账号重新登录继续；主动退出或关闭应用结束流程。内容实际失效时不得继续。
- 首版仍为进程内进度，不承诺跨重启恢复。不新增平台客户识别、自动发送、退款执行、医学诊断、考试和积分。

### 冻结维护结构

一个工作簿包含场景目录、执行任务、判断分支、客户话术、知识与案例、资源与图片六张表。六类分别持有稳定编号，不能用物理行号建立业务身份。纯操作任务无需伪造话术。分支目标必须显式引用，阶段名称只用于导航。配套与替代话术明确区分。

新增分配编号，修改保留编号，停用显式声明。缺行继承，不等于删除。被引用内容不能孤立停用。恢复沿用原编号并产生新版本。业务维护状态和系统发布回执分开。格式标识、规则、映射及结构摘要一起冻结；不能复用旧六工作表解析器的版本标识。

最新原工作簿仅作为仓外受控迁移依据。本轮不重写真实内容。原记录逐条保留映射去向；类型识别进入知识或判断依据，内部动作进入任务，其他品牌资料不得自动继承 Menokin 范围。图片和公式对象必须验证实际字节，不能只统计单元格。

### 发布、读取和失效语义

1. 候选必须持有完整引用闭包。发布在既有事务中同时固定场景、节点、分支、知识、话术、资源绑定与版本。部分失败不切换当前版本，不留下只有一半的流程。
2. 来源候选内容与适用资格一起验证。坐席必须能读到所有可达任务和必需知识。不可通过过滤受限节点造成断边，再让客户端猜下一步。主管资料可独立授权，但不能成为坐席必经节点。
3. 学习目录可分页，单个流程必须完整校验后才可开启。若合同沿用分页快照，所有页必须绑定相同 release、contextGeneration、来源和流程版本，完成校验之前不渲染可执行半图。超预算显式失败，不截断节点；具体字节和数量预算由合同评审按现有边界确定。
4. 正常新发布不静默改写正在执行的旧版本。旧版本只能在原资格及有效期内继续。旧版本保留期限和容量回收由数据库合同确定，不能因 Main 持有正文而绕过服务端撤权。
5. 登出、店铺/资格变化、权限撤销、有效期截止后，清理相关正文、资源和复制句柄。网络中断无法确认授权时禁止继续执行和复制。学习浏览同样失效，不能仅给 Query 加门禁。
6. 每次复制由 Main 对当前内容版本、资格有效性、步骤修订和话术选择共同校验。renderer 只发送意图和受控选择标识，不传任意正文或主体。复制成功只更新复制反馈。
7. 图片按当前资格读取并在返回前重新核验，缓存按版本及权限范围隔离。撤权清除缓存。图片字节与描述符不一致时拒绝展示，不回退未经授权的历史字节。
8. 发布超时或提交结果未知时恢复原操作，不能重新创建发布。取消等待不等于回滚。回退复用既有回退流程并重新核对当前权限和依赖，不覆写不可变历史。

### 正式消费与旧实现退出

P3c 更新 contracts 生成物及数据库/API 的获准增量。P4b 将 Main 的受控 usage 投影转换为唯一 SopTree 后交给现有执行器。学习使用相同发布定义但独立资格。renderer 不导入数据库 schema，不通过新通用 IPC 拉取任意字段。

来源版本显式选择旧行式 SOP 或新执行图解析。旧来源继续由既有消费者处理，不凭名称删除管理模块。新执行图来源不得退回旧行式解析或合成树。新路径启用后，与其对应的旧字段、适配器及调用方同波迁移删除；冻结旧合同只按治理流程保留历史，不手工删快照。

### 统一模型的实施选择

比较两种边界：分别维护六表、七表的发布模型及执行器，会重复版本、权限和进度规则；以一份版本化任务图承接不同来源的解析结果，可以复用已有发布、资格和 Main 会话。选择后一种。六表维护稿、用户原始工作簿和七表候选只有经过显式来源登记及映射时才能进入该模型；不因为已有七表样板就要求维护者同时维护第二份工作簿。当前七表代码尚未正式交付，后续只保留实际来源或兼容需要的解析能力，不保留两套执行状态机。

统一图以来源、流程和版本标识一个流程，以任务编号标识当前步骤。任务持有操作要求、必要确认、知识、资源和可分别复制的多条话术；判断分支显式保存目标、依据和无法判断选项。服务端拥有完整发布和权限投影，Main 拥有当前会话与进度；学习和执行从同一发布定义读取。图片必须能关联任务、知识和话术，并按实际资格读取。六表缺少的入口、识别词和分支顺序须在维护或映射时显式提供，不能从正文和物理行号猜出。

| 停用 | 表达 disable；必须确认该来源存在可停用的历史条目，不能以停用创建新条目 |
| 物理缺行 | 继承现有条目，绝不自动删除；导出预览明确提示该行为 |
| 恢复 | 复用原编码表达 upsert，重新校验有效期和范围 |
| 纯内部步骤 | 保留维护材料，不为满足 answerText 必填生成虚假对客回复 |

首次迁移的必需输入是：已登记 sourceId、对应品牌/店铺范围、领域、原有条目编码清单、上一发布版本与新模板版本组合。它们来自授权读取和正式登记，不由本地脚本编造。新格式的 templateVersion、ruleVersion、mappingVersion、structureSha256 必须一起冻结；当前维护表表头由 `SOP_MAINTENANCE_HEADERS` 拥有，冻结时对确定序列计算摘要并在合同测试中核对。

资源发布需额外确认稳定资源编码与 objectId 的映射、支持的 MIME/单图/单条/总量预算、跨条目复用规则、可见对象、取图资格及撤权失效。已有图片提报里的快照页上限需要与真实分页和每条图片上限联合验证，不能仅因给出一个常数就认为不会截断。文字和图片绑定必须在同一候选版本中确认，失败不能留下半发布状态。
