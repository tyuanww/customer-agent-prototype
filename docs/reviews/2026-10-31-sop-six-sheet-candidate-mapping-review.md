# 真实六表候选映射审阅卡

状态：`CANDIDATE`、`review-only`、不可发布。

这张审阅卡只登记业务身份、对象类型和流程设计边界。它不读取工作表正文，不把物理行号、标题或图片顺序当成业务身份，也不进入 Query 召回。

## 候选身份

| 工作表 | 候选编号 | 类型 | 候选入口 | 候选设计边界 |
| --- | --- | --- | --- | --- |
| 过敏流程SOP | `menokin.sop.allergy` | SOP 家族 | 过敏、疑似过敏 | 坐席判断，信息不足时补充确认，不转人工 |
| 长痘痘SOP | `menokin.sop.acne` | SOP 家族 | 长痘、痘痘 | 先确认问题场景，再按业务结果进入步骤 |
| 少错破SOP | `menokin.sop.shaocuopo` | SOP 家族 | 少错破 | 先确认正式业务名称和入口词，再拆分任务 |
| 品质售后SOP | `menokin.sop.quality-after-sales` | SOP 家族 | 品质问题、质量问题、售后 | 先判断问题类型，再进入处置步骤；补偿和退货权限必须显式配置 |
| 税收相关规则 | `menokin.rule.tax` | 规则集 | 无直接 SOP 入口 | 只能作为检索规则或任务知识被引用 |
| 品牌对接资源汇总 | `menokin.resource.brand-integration` | 资源集 | 无直接 SOP 入口 | 只能作为流程引用资源，不自动生成任务 |

所有候选身份都保持 `enabled=false`、`runtimeEnabled=false` 和 `publishable=false`。机器来源是 [六表候选登记](../sop-real-six-sheet-candidate-registry.json)。

## 统一流程结构

SOP 家族统一采用以下候选结构：

```text
入口候选
  ↓
补充确认
  ↓
坐席判断
  ↓
业务结果分支
  ↓
下一任务或结束
```

规则集和资源集不进入这条启动流程。它们只能作为检索结果或已绑定资源出现。

## 各表最小确认项

| 工作表 | 业务方需要确认的最小内容 |
| --- | --- |
| 过敏流程SOP | 结果分支名称、判断条件、目标任务、原表行区段、所有者、范围、可见对象和有效期 |
| 长痘痘SOP | 正式业务名称、入口排除词、结果分支、目标任务、原表行区段、范围、可见对象和有效期 |
| 少错破SOP | 正式业务名称、入口词、任务边界、结束条件、原表行区段、所有者、范围和有效期 |
| 品质售后SOP | 问题类型、处置分支、补偿或退货权限、图片归属、原表行区段、范围和有效期 |
| 税收相关规则 | 规则所有者、适用范围、生效区间、可见对象和信息不足路径 |
| 品牌对接资源汇总 | 资源所有者、资源用途、图片归属、适用范围、可见对象和有效期 |

## 命名规则

- 稳定编号使用英文语义短名，不使用行号。
- 坐席显示名称使用“业务状态 + 下一步动作”。
- “其他”“情况一”“正常”“异常”不能作为正式分支名称。
- 入口词和排除词必须由业务方确认，不能从正文自动推断。
- 规则集和资源集没有直接 SOP 入口词。
- 业务语义不完整时保持候选状态，不生成正式 graph。
