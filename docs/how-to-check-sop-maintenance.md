# 核对 SOP 手册维护稿

本命令只检查仓外维护稿，不注册来源、不上传文件、不发布内容。当前本地格式为 `sop-manual-authoring-v1.1`，尚未冻结或注册，与运行时旧六工作表 SOP 协议不同。旧三表维护规则已退出本工具。

## 准备六张工作表

先构建解析包，再生成空模板。输出路径必须尚不存在。

```sh
pnpm --filter @customer-agent/content-intake build
node scripts/check-sop-maintenance.mjs --template /absolute/SOP手册维护模板.xlsx
```

工具自动写好版本和表头，不含真实或合成业务正文。空模板检查会返回 `EMPTY_DATA`，填写完整场景后再检查。

每张表的 A1 填写一次 `sop-manual-authoring-v1.1`。第一行其他单元格留空。第二行使用下列固定表头，第三行开始填数据。版本不要求逐行填写。

原本地 `sop-manual-authoring-v1` 六表仍按原表头只读检查，但它没有入口词、匹配词、分支顺序、话术关联编号及结构化确认项；这些内容会显示为待核对，不能从标题、正文或行位置推断。旧话术行保留一份正文和原任务、条件及关系，关联编号为空；旧“必须确认的信息”按原样保留，不拆成确认项，空白也不能解释为无确认项。要补全这些字段，应使用新模板并由维护者明确填写，不要只修改旧稿的 A1。六张表不能混用版本。

先前的 `sop-manual-authoring-v1.1-draft` 标识不再读取；如已有此版本的草稿，须核对匹配词并转入新模板，不能只改 A1 后假定语义不变。

本轮表头修订前的本地 `v1.1` 草稿也需由维护者按新表头重新填写；即使 A1 相同，旧表头仍会被拒绝，不会静默套用新字段语义。

六张表末尾统一增加 `维护状态 | 业务确认人 | 待确认事项` 三列。表头顺序由 `packages/content-intake/src/maintenance.ts` 的 `SOP_MAINTENANCE_HEADERS` 唯一维护。

| 工作表 | 业务字段，按顺序填写 |
| --- | --- |
| 场景目录 | 场景编号、场景名称、适用范围、起始任务编号、入口词、生效时间、失效时间 |
| 执行任务 | 记录类型、任务编号、场景编号、阶段、任务名称、任务类型、操作要求、确认项配置、下一任务编号、关联知识编号、关联资源编号、可见对象、关联编号、话术编号、适用条件、话术关系、确认项编号、确认项文字、确认项顺序 |
| 判断分支 | 分支编号、任务编号、选项、判断依据、目标任务编号、是否无法判断、匹配词、分支顺序 |
| 客户话术 | 话术编号、话术标题、对客正文、关联资源编号 |
| 知识与案例 | 知识编号、标题、正文、可见对象、关联资源编号 |
| 资源与图片 | 资源编号、资源类型、资源名称、可见对象、适用范围、资源内容、图片 |

所有单元格使用文本，不使用公式或合并单元格。场景、任务、分支、话术、话术关联、知识和资源的主编号在六表中唯一；确认项以“任务编号＋确认项编号”标识，确认项编号在同一任务内唯一。引用行中的任务编号和话术编号是外键，允许重复出现。建议按记录类型使用不同编号前缀。编号采用英文字母或数字开头，后续可用字母、数字、点、下划线、冒号和连字符，总长最多 64 个字符。排序、插行和文字修改不换编号。多个关联编号用英文逗号分隔。

“执行任务”表以记录类型区分三种行；每行只填写本类型字段及三列维护信息，其他业务字段留空。记录类型缺失或填入其他类型的字段会被拒绝。

| 记录类型 | 本行填写的业务字段 |
| --- | --- |
| 任务 | 任务编号、场景编号、阶段、任务名称、任务类型、操作要求、确认项配置、下一任务编号、关联知识编号、关联资源编号、可见对象 |
| 话术引用 | 关联编号、任务编号、话术编号、适用条件、话术关系 |
| 确认项 | 确认项编号、任务编号、确认项文字、确认项顺序 |

客户话术表每个话术编号只有一行正文。需要复用时，在执行任务表分别填写多个话术引用：例如任务 `TASK-A` 的 `LINK-A` 和任务 `TASK-B` 的 `LINK-B` 都引用 `SCRIPT-A`，各自填写条件和 `独立`、`替代` 或 `配套`。同一任务不得重复引用同一有效话术；可以保留停用的历史引用。条件为非空文本，最多 1024 个 Unicode 字符。纯操作任务可以没有话术；操作要求只写在任务表，对客正文只写在话术表。本工具不判断对客正文是否合适，仍需业务审核。

任务的“确认项配置”填写 `有确认项` 或 `无确认项`。留空表示尚未填写并报告待核对；不能因为没有确认项行就推断为无确认项。选择有确认项时，为每项添加确认项行，显式填写稳定编号、所属任务、文字和顺序；若没有有效确认项行则报告待核对。选择无确认项时不能存在有效确认项行，停用的历史行仍可保留。确认项文字非空、最多 1024 个 Unicode 字符；每个任务最多 32 个有效确认项，顺序为文本 `1` 到有效项数，不能重复或跳号。顺序留空表示待核对；编号缺失、重复或引用无效时拒绝解析，不会生成编号或返回部分文档。

任务类型填写 `操作`、`判断` 或 `终点`；阶段留空时报告待核对。操作任务填写下一任务编号。判断和终点任务不填写默认下一任务。判断任务至少两个有效选项，且必须恰有一个 `是否无法判断=是` 的选项。同一任务的有效分支选项按展示空白归一化后必须不同，例如“合成  选项”和“合成 选项”不能同时使用；检查不改动原文。未知情况指向补充材料或人工协助任务，不留空、不猜目标。分支不能跨场景，任务图不允许循环；等待和恢复属于同一任务状态。每个有效任务必须能从所属场景入口到达。

场景的入口词与分支的匹配词分别填在对应单元格内，一行一个词项。每组最多 32 项，每项最多 128 个 Unicode 码点，例如一个表情计为一个码点；不得包含 NUL 或孤立代理项。同一单元格不得重复或在词项之间留空行。除下述转义外，工具保留原文和词项首尾空格，不替维护者规范化或生成词项。当前合成桌面分支校验使用相同长度和空格规则；匹配时对临时值做 NFKC、小写和去首尾空格，不修改保存的原文。场景入口词在合成桌面尚无此动态映射。不同分支可以填写相同匹配词：后续识别可能出现多个候选，仍须由坐席人工确认，不能自动推进。

每个判断任务的有效分支分别填写文本 `1`、`2`，最多到 `4`；同一任务内顺序不得重复，且须从 1 到有效分支数连续编号。排序或插入 Excel 行不会改变已填写的顺序。入口词、匹配词或顺序留空均报告待核对，包括状态为待发布或启用的记录；解析结果以 `null` 保留缺项，不能解释成已确认值。

分支的“匹配词”整个单元格填写 `不设置`，表示明确不配置匹配词，解析为 `[]`；留空仍是待核对，解析为 `null`。如果需要把字面 `不设置` 当成唯一词项，请写 `\不设置`。若词项本身以反斜杠开头且其余文字为 `不设置`，再多写一个反斜杠：例如 `\\不设置` 表示词项 `\不设置`。转义按每一行处理；`不设置` 与其他词项分行填写时，它只是一个普通词项。入口词不使用此特殊写法。

任务和知识的可见对象填写 `坐席可读` 或 `主管可读`。资源另外允许 `对客可用`。坐席路径不能依赖主管专属知识或直接进入主管任务。客户话术只能关联对客可用资源，不自动扩大权限。

资源类型填写 `图片` 或 `资料`。首版图片仅支持 PNG 和 JPEG；GIF 必须先转换后重新导入，不能删除图片后当作完整稿。图片须使用本表对应资源行“图片”列的单元格锚点，且图片不能跨行；绝对锚点、背景图及无法完整读取的图片归属会被拒绝。工具按工作表核对 drawing 图片对象及其关系；普通无图片的图形和表格不计为图片，无法确定归属的图形图片会被拒绝。图片起点偏移按当前 ExcelJS 定位边界校验，越过其列边界的偏移不被接受；必要时将起点靠近图片列左边界。单元格写图片名称不算有图。同一资源可以嵌入多张图片。资料填写资源内容。本工具不访问资源中的网址。场景及资源的适用范围不得为空，不能用空值表达通用；`待确认` 即使前后有空白仍表示待核对。

## 执行检查

1. 使用 Node 24 和项目锁定的 pnpm，构建解析包。

```sh
pnpm --filter @customer-agent/content-intake build
```

2. 指定仓外输入和一个尚不存在的报告路径。

```sh
node scripts/check-sop-maintenance.mjs /absolute/input.xlsx /absolute/report.json
```

3. 根据报告的工作表、行和列修正维护稿。报告只包含模板版本、计数、坐标和固定错误说明，不包含正文、任意输入编号、内部地址、图片或未知工作表名。

退出码 2 表示结构无效，3 表示业务核对未完成，0 表示本工具检查通过。`entries` 只统计任务行，`counts` 分别列出六表的全部数据行，包括话术引用和确认项。普通检查的 `sourceCheck` 始终为 `not-checked`：即使模板检查结果为 `reviewed`，也没有核对来源。所有结果的 `publishable` 均为 `false`。

报告使用新文件写入，权限为仅当前用户读写；已有路径拒绝覆盖。维护稿和图片留在仓外，开发验证使用合成资料。

### 合成来源对账

开发验证中，带 `SOP-SYNTHETIC-ONLY` 标记的来源可与映射决定和当前维护稿一起重新核对。四个参数均使用绝对路径，报告路径必须不存在：

```sh
node scripts/check-sop-maintenance.mjs --source /absolute/source.xlsx /absolute/decisions.json /absolute/maintenance.xlsx /absolute/source-report.json
```

报告绑定来源、映射决定和当前维护稿的摘要，并比较重新生成的工作簿内容。更改维护稿后需要重新核对；待处理来源、无法支持的对象以及未核对的图片会阻止 `sourceCheck: complete`。当前工具还不能完整解码和确认图片归属，含图片的来源会保留待核对。此入口仅供合成验证，不能用于真实业务资料或正式发布。

## 处理新增、修改与停用

维护状态填写 `待核对`、`草稿`、`待发布`、`启用` 或 `停用`。待核对、草稿及任何未决事项阻止返回 `reviewed`。待发布、启用和停用必须填写业务确认人；空白或 `待确认`（包括前后有空白）仍表示待核对。手填姓名不替代服务端身份验证。

新增内容分配新编号，修改保留编号。停用必须显式表达并处理所有有效引用。整条依赖链协调停用只说明维护意图一致，不代表线上已撤回。缺行不自动删除，空表不表示清库。

生效和失效时间可暂不填写。填写时使用带时区的 ISO 时间，例如 `2026-11-01T09:00:00+08:00`。失效时间必须晚于生效时间。正式发布仍须按批准合同处理空值、有效期和范围。

## 检查通过后核对发布条件

本工具不读取登记来源或上一发布版本，不执行导入、停用、权限变更或回退。它不核验维护者身份，也不判断退货、补偿或健康表述是否正确。引用完整性检查不替代业务规则审核。

新六表尚不是已注册运行输入。正式接入需要冻结模板、规则、映射、带确认项顺序的图结构、媒体、版本和资格合同，再通过既有候选、审核及发布事务消费。解析结果中的作者姓名和状态只是原表声明，不是已认证审核；不得把本工具的 `reviewed` 当作业务已批准、可以上传或已获准上线。
