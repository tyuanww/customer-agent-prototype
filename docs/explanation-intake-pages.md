# 为什么岗位和登录是分开的

总监要在已有资格范围内给客服授查询，或给客服主管授上传、核对和发布。外包坐席需要一个账号密码，但这个账号不能变成第三种岗位，也不能顺便打开生产或换一套登录系统。

## 问题

如果页面自己发明岗位、自己发主体 ID，或者新建坐席立刻从 `127.0.0.1:43101` 登录，资格、口令和身份会绑在界面上。换一台机器或重启身份服务之后，页面上的人就和库里的人不一致。独立的 Keycloak、Casdoor、Logto 或 Ory 还会逼现有飞书登录和合成口令一起迁移。

窄窗口如果改成手机底栏，1180×760 的桌面工作台会被拆成另一套导航。审查时低于 980×680 的浏览器宽度已经把内容列挤成竖排，那不是办公机上的窗口。

## 做法

岗位只有「客服」和「客服主管」，映射到已经存在的动作。客服恰好是 `query`。客服主管恰好是 `content-manage`、`import`、`source-confirm`、`publish`。回退、取消候选和旧审批不进这两个岗位。

页面只提交意图。谁有资格、范围句柄和写请求留在 Main。口令文件留在合成栈，不进页面状态。

新建坐席在 Electron 里写人员行和口令哈希。身份服务每次 `POST /password` 都重读口令文件；读失败是 503。已登记主体改了哈希，不用重启就能登录。`/password` 与 `/exchange` 仍只交换启动时登记的合成主体，注释写明新坐席不加入这组名字。所以哈希可以落在 `password-accounts.json`，这个人仍然不能从 43101 登录。

`preview=intake` 是给设计审查看布局的。list、create、reset、disable 只改内存。它不能用来验收登录。

工作台最小窗是 980×680。更窄时保持同一侧栏。分组字用 11px，满足辅助信息的下限。不把外壳改成手机导航。

`productionConsumerReady` 保持 false。这两页不打开生产消费，不改版本号，不改冻结合同。

## 取舍

新外包坐席现在不能自助登录，也不能改自己的密码。管理员在权限页设定和重置密码。要让新坐席登录，得单独改身份服务接受的名字，并证明口令文件和交换名单一致。那不是这两页的范围。

不接独立身份系统，现有飞书登录和合成口令可以继续用。多个系统要共用登录、坐席要自助改密或要多因素认证时，再单独立项。

## 没采用的做法

- 用 Keycloak、Casdoor、Logto 或 Ory 替换当前登录。
- 在页面上增加第三种岗位，或把回退、取消候选、旧审批配给客服主管。
- 让预览页或新建坐席从 43101 登录。
- 低于最小窗时改成手机导航。
