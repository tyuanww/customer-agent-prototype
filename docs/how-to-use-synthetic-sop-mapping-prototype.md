# 用合成表格演示 SOP 来源整理

本原型只接收带 `SOP-SYNTHETIC-ONLY` 创建者标记的合成工作簿。不要把标记加到真实资料上。标记只能防止误操作，不能证明内容是合成的。

原型不会上传、审核或发布内容。输出固定为 `publishable: false`。图片没有完成解码和原始显示比例核验，即使指定了去向，来源核对仍显示待核对。

## 体验合成示例

先构建解析包，再生成一组新的合成文件。输出目录必须不存在。

```sh
pnpm --filter @customer-agent/content-intake build
node packages/content-intake/scripts/sop-source-mapping-demo.mjs /绝对路径/新的合成示例目录
```

打开 `合成整理表-空白.xlsx` 的 `来源整理` 查看未处理的来源。打开 `合成整理表-已填写.xlsx` 查看拆分、合并、手工分支和图片去向。整理表不再另存文字盘点预览，避免出现与原表不一致的副本。`合成输出` 目录中的 `合成维护稿.xlsx` 和 `合成核对结果.xlsx` 是实际转换结果。

## 整理另一份合成原表

1. 工程人员生成整理表。输出文件必须不存在。

```sh
node packages/content-intake/dist/sop-source-mapping-cli.js prepare /绝对路径/合成原表.xlsx /绝对路径/合成整理表.xlsx
```

2. 整理人员打开整理表，先在六张目标表添加记录。每条记录填写唯一的英文或数字 `整理行号`，例如 `TASK1`。其余字段使用目标表中的表头。来源填入的目标字段留空。来源整理表和目标表不要合并单元格、插入图片或使用批注。
3. 对确定属于同一正文的原表区域，在 `批量整理` 中填写原表、单元格范围、处理方式、目标行号、正文目标字段和合并方式。区域只能整块覆盖合并单元格。不同批量区域不得重叠，也不能覆盖已拆分或已单独处理的文字。单个目标字段最多使用 1000 个来源片段。图片和不支持的对象不会随区域自动处理。
4. 对没有批量处理的内容，在 `来源整理` 表选择处理方式。选择 `使用` 时填写目标表中的整理行号和目标字段名。选择 `排除` 时填写处理说明。无法判断时保留 `待确认`。
5. 拆分文字时，复制该来源整行，在两行分别保留前半段和后半段。所有分段按表格行顺序拼接后必须与原文完全相同，不能删除空格、换行或标点。需要把多个来源合到同一个字段时，在所有相关行选择相同的 `直接连接`、`换行` 或 `空格`。仅使用逐项整理时，合并顺序以来源整理表的行顺序为准；如果其中使用了批量规则，该字段的所有来源按原表的工作表顺序、行、列和同格分段顺序排列，与整理表及批量规则的行顺序无关。
6. 查看 `图片盘点预览`，再把图片的目标行号填为 `资源与图片` 表中对应的记录，目标字段填 `图片`。在任务、知识或话术记录中手动填写资源编号，明确使用关系。背景图也必须单独决定。图片预览中的文字使用明确的 Arial 字体；未知字体、字体主题替换或符号字符集会阻止转换。图片预览表不能排序、筛选、合并或使用条件格式；图片、编号、摘要、锚点、标签显示格式或主题颜色改变时，转换会停止。从右向左的图片预览也需要先恢复原视图。图片内部绘图变换及实际字体渲染未自动确认，须对照原表核对图片和编号。
7. 判断分支和纯人工新增的记录由整理人员填写在目标表。无来源的新增记录必须填写 `新增说明`。系统不根据位置、措辞或表格顺序生成分支。批量整理不能填写分支目标。
8. 工程人员生成维护稿和核对表。输出目录必须不存在。

```sh
node packages/content-intake/dist/sop-source-mapping-cli.js build /绝对路径/合成原表.xlsx /绝对路径/合成整理表.xlsx /绝对路径/新的输出目录
```

查看 `合成核对结果.xlsx`。`预期来源去向` 按分段显示使用、排除和待确认情况。`预期目标记录` 显示目标行号与业务编号。`预期字段来源` 分别列出原表片段和人工填写的字段。`当前实际维护稿` 显示选定的当前字段，包括话术引用的适用条件和关系、确认项文字与顺序。其他字段没有逐项展示。`图片归属` 并列显示预期和当前实际关联；有图片时，概览和逐图均提示预览绘图变换待核对。`维护稿问题` 显示当前文件中的错误位置。

`来源覆盖` 只表示所有来源已指定去向或说明排除原因，不表示内容或图片已经审核。业务审核显示 `未核验`，不推断外部是否已有审核。新整理表不提供业务确认人输入。旧整理表中的姓名和状态不会进入生成稿；生成稿统一为草稿。认证业务审核仍由正式审核机制完成。命令退出码始终为 3，输出仍会生成。

## 修改维护稿后重新核对

维护稿不应作为第二份来源决定。若修改过维护稿，使用原表、整理表和当前维护稿生成新的核对表。输出文件必须不存在。

```sh
node packages/content-intake/dist/sop-source-mapping-cli.js verify /绝对路径/合成原表.xlsx /绝对路径/合成整理表.xlsx /绝对路径/合成维护稿.xlsx /绝对路径/新的核对结果.xlsx
```

核对表分别显示整理表生成的预期和当前实际维护稿。如果工作簿内各文件的内容一致，概览显示 `是（工作簿内各文件内容一致）`；ZIP 压缩方式和容器元数据不在该比较范围内。如果已比对的内容或图片位置发生变化，概览显示 `否`。工具比较文字、行列、合并关系、对象、图片摘要与锚点、样式及行列可见性，不检查工作表视图、打印布局和图片完整解码。文件元数据变化且已比对部分一致时，概览显示 `已比对内容及格式一致（视图未核对）`；这不是完整语义一致。如果内容和图片的已比对部分一致，但样式、主题或行列尺寸不同，概览显示 `已比对内容及图片一致，格式和视图待核对`，不要求重新填写来源映射。遇到无法识别的对象或结构时，概览显示 `无法确认`。这些结果都不是业务审核。

## 运行大表合成演示

```sh
node packages/content-intake/scripts/sop-source-mapping-batch-demo.mjs /绝对路径/新的大表合成目录
```

演示生成 1200 个文字对象和 1 张图片。六个已知的原表区域各对应一条知识正文。脚本填写六条批量规则、九条目标记录，并单独指定图片。`合成填写项统计.json` 记录写入的 89 个非空填写项：批量规则 36 项，目标记录 50 项，图片去向 3 项。这不是鼠标点击数或人工耗时，也没有计算阅读、判断和审核工作；真实工作簿的块数与去向可能不同。

## 当前限制

- 首版 SOP 仅导入 PNG 和 JPEG。来源盘点保留 GIF 的字节和位置并提示转换；映射或排除 GIF 都不能使来源核对变为完成。转换后重新生成盘点和整理表。

- 当前只有离线命令和 Excel 整理表，没有接入桌面产品。业务人员填写表格仍需要工程人员生成、转换和核对。
- 一段文字只能直接指定一个目标字段。要在多个任务复用同一内容，需在维护表中显式建立现有业务引用；原型不自动复制来源决定。
- 图片只能指定到一条资源记录，再由维护人员在任务、知识或话术中填写资源编号。Arial 名称校验不能证明目标设备已安装该字体或各应用的实际渲染一致；预览、转换和关联都不代表图片完整解码或业务确认。
- 六表是本地维护草稿，尚未接入正式图合同和发布服务。分支是否正确、话术是否适用、图片是否匹配均需业务人员审核。
- 来源文件仍按文件摘要绑定。SHA-256 不一致时会先提示原表与整理表不匹配。即使原表仅重存且内容未变，也不能直接替换旧原表；保留旧原表可继续使用已有整理表。尚未实现对新原表的安全重绑定。
- 目标行号和字段名需要手填，拆分依赖复制整行。批量入口只接受已知矩形区域与正文目标，不推断场景或流程。若后续需要大量整理，可在桌面提供来源选择、拆分和去向选择，但应继续复用同一份来源盘点、核对和发布机制。
