# macOS M5 人工核验清单

本页是 **macOS 合成查询体验的人工门禁**。由人在本机 Mac 上看窗口、点控件、读颜色与文案、查系统剪贴板。勾选只表示该项被真人观察并成立。

> **本页不是 M5 完成声明。** 写完、提交或合并本清单，都不等于 M5 已通过。未观察项保持空白。不得把 unit、CI、Playwright 或 adapter 测试的绿写成「Mac 人工已接受」。

相关文档：[如何验证桌面 Demo](how-to-verify-desktop.md) · [第一次运行](tutorial-first-run.md) · [执行清单](plans/2026-09-06-execution-goal.md)

## 1. 开始前（仍不是本门禁）

本机环境：

```bash
export PATH="$HOME/homebrew/opt/node@24/bin:$HOME/homebrew/bin:$PATH"
hash -r
node -v    # 需要 v24.x
pnpm -v    # 项目锁定 11.19.0
```

合成栈必须已经在跑（隔离 PG15 + 合成身份 + API + worker + 已发布的合成话术）。启动与停止见 [如何验证 · 本机合成栈（M1）](how-to-verify-desktop.md#本机合成栈m1)，例如：

```bash
node scripts/synthetic-stack/stack.ts start
node scripts/synthetic-stack/stack.ts status
```

客户端二选一，并在记录里写明走的是哪条：

| 路径 | 配置从哪来 | 何时用 |
| --- | --- | --- |
| 开发态（`启动客服Agent.command` 或 `stack.ts desktop` 打出的 `pnpm dev`） | 环境变量 `CUSTOMER_AGENT_DESKTOP_API_ORIGIN` / `CUSTOMER_AGENT_DESKTOP_IDENTITY_ORIGIN` | 日常人工观察 |
| M4 本机未签名包 | 应用 userData 下的 `synthetic-stack.json`；**打包态忽略上述环境变量** | 仅当本次真的打开了 M4 未签名 `.app` |

禁止：真实飞书 URL / 凭据、真实客户数据、把未签名包发给别人、购买或使用签名公证、Windows 包。

每项只许填：**通过** / **未通过** / **未观察**。未触发的失败路径填 **未观察**，不要填通过。

## 2. 合成登录：成功不是红色校验条

观察对象是 Query 胶囊里的会话提示，不是 Playwright `data-testid` 断言。

颜色合同（人眼）：

| `kind` | 文案 | 颜色 | 不得与之混淆 |
| --- | --- | --- | --- |
| 未登录 `unsigned` | `请先合成登录`（退出后为 `已退出，请先登录`） | 正文色，不是红校验 | 失效、失败、输入校验红字 |
| 成功 `success` | `合成登录成功，请确认平台和商品后查询` | **非红色**（成功色） | `.validation-error` 红字、「合成登录…」残留红条 |
| 失效 `expired` | `登录已失效，请重新登录` | 危险色 | 未登录提示、登录失败 |
| 失败 `failed` | 例如关掉登录窗 → `操作已取消`；登录窗超时/身份方不可达 → `服务暂不可用，请重试` | 危险色 | 未登录、失效、成功 |

人工步骤：

1. 打开 Query。未登录时点查询：只应看到未登录提示 `请先合成登录`，**不是** 输入校验红横幅。
2. 点「合成登录」，走独立窗口「合成身份登录」（合成 loopback，禁止飞书）。成功后：
   - 按钮变成 `{角色} · 退出`（合成坐席一般为 `agent`）；
   - 悬停可见到期时间；
   - 成功提示为上表成功文案，**不得** 占用输入框下的红色 `invalidMessage`。
3. 关掉登录窗或让登录失败：提示为失败 `kind`，文案与未登录、失效都不同。
4. 已登录会话恢复（例如收起再打开 Query，或进程仍持有加密会话）：不得残留红字成功条，也不得把恢复误报成一次新的失败。
5. 点退出：立即回到未登录，提示 `已退出，请先登录`，本地会话清掉。这是 `unsigned`，不是 `expired`。
6. 若能等到到期，或会话已被撤销：提示必须是 `登录已失效，请重新登录`，不得仍显示成功条，也不得写成「请先合成登录」那种从未登录过的口吻。

勾选：

- [ ] 登录成功是非红色成功提示，不是红色无效横幅
- [ ] 未登录 / 成功 / 失效 / 失败 四种提示可被人眼区分
- [ ] 恢复已登录会话没有残留红字
- [ ] 未把 unit / Playwright 登录用例当作本项通过

## 3. 商品目录：只选自 SSOT，禁止手填商品标识

商品范围控件在查询结果区，图例为 `查询范围 · 合成数据`。目录唯一来源是 `apps/desktop/src/shared/synthetic-catalog.ts`，下拉显示 **label**，回传 **id**。renderer 不得提供自由文本商品框。

当前合成目录人眼应看到的 **中文 label**（不得把内部 id 当选项文案）：

| 品类 label | 其下具体款 label |
| --- | --- |
| 洁面 | 澄芽氨基酸洁面乳 |
| 精华 | 雾屿舒缓精华 |
| 防晒 | 月白清透防晒乳 |
| 面膜 | 露芷修护面膜 |

下拉里若出现 `cat_cleanser`、`sku_chengyajiemian` 等 id，或仍有「合成商品标识」手填输入框，本项失败。

人工步骤：

1. 登录后输入问题、选平台（先选「千牛」）。
2. **全店**：商品范围保持「无具体商品（仅全店话术）」，查询「什么时候发货」。应能得到全店发货话术。目录即使稍后不可用，全店也必须仍可走这条路径。
3. **品类**：商品范围改「品类」，品类下拉只出现上表 label；选「洁面」后查「洁面怎么用」。换品类必须清掉旧结果、停掉未完成的复制。
4. **具体款**：商品范围改「具体款」，先选品类再选具体款；具体款下拉只列出该品类下的 label（例如洁面 → 澄芽氨基酸洁面乳）。不得手填 SKU。选「澄芽氨基酸洁面乳」后查对应用法。
5. **目录缺失 / 失败 / 不一致（fail-closed）**：品类或具体款查询必须明确失败，文案含「未猜测商品，未扩大为全店」。不得静默改成全店，不得猜测商品。示例文案：
   - `合成商品目录不可用，无法按品类或具体款查询。未猜测商品，未扩大为全店。`
   - `合成商品目录配置不一致，无法按品类或具体款查询。未猜测商品，未扩大为全店。`
   - `所选商品不在当前合成目录中，请重新选择。未猜测商品，未扩大为全店。`
6. 同一会话把商品范围改回「无具体商品（仅全店话术）」后，全店发货查询仍须可用。
7. 正常合成栈上目录通常是可用的。若本次 **没有** 真的看到目录缺失/失败，第 5 步记 **未观察**，不要用 `catalog-scope` unit 测试勾选。

勾选：

- [ ] 品类 / 具体款选项来自 SSOT 中文 label，不是内部 id
- [ ] 界面没有商品标识手填框
- [ ] 全店（无具体商品）在目录可用时能查
- [ ] 目录缺失或不一致时品类/具体款 fail-closed，且未扩大为全店（若未触发则记未观察）
- [ ] 目录不可用或改回全店后，全店查询仍可用（若未触发缺失则至少验证「改回全店仍可用」）
- [ ] 未把 Playwright 目录用例当作本项通过

## 4. 复制只进剪贴板；无命中辅导；合成标注可见

复制成功的按钮/toast 文案是 `已复制`。合同写明：复制成功只表示写入系统剪贴板，不表示发送、采纳、正确或问题已解决。界面不得出现「已发送」。

人工步骤：

1. 命中一条候选，点「复制话术」（或数字键 1/2/3）。按钮变为「已复制」。
2. 在「文本编辑」或其它应用里粘贴：必须是刚才那条话术原文。
3. 确认没有把内容发到飞书、聊天工具或任何远端。本 Demo 无代发。
4. 每张话术卡可见 `DEMO · 合成数据`。查询范围图例为 `查询范围 · 合成数据`。登录入口是「合成登录」。有占位符时输入框标签是「合成订单号」或「日期」，填的也是合成值。
5. **无命中辅导**：登录并选好平台后，查询一条合成栈不会命中的问题（不要用真实客户原话）。应看到「没找到可用话术」，以及请客户稍等、联系话术师/运营的辅导。若出现「复制合成联系方式」「打开合成入口」：
   - 复制联系方式只把合成联系卡写入剪贴板；
   - 打开入口只表示入口窗口已打开；
   - 状态停留在「待核实」/「已打开入口」/「已复制联系方式」；
   - 明确 **不是** 转交回执，不得理解成已经转交成功。

勾选：

- [ ] 复制后系统剪贴板确有话术原文，且界面只说「已复制」
- [ ] 全程没有发送、没有「已发送」
- [ ] 合成标注在登录、查询范围、候选卡上均可见
- [ ] 无命中辅导可见；打开入口 / 复制联系方式不被当成转交成功
- [ ] 未把复制相关 unit / E2E 当作本项通过

## 5. 回退后的 STALE：不能因为还能搜到发货话术就勾

历史误判：有人回退后再次查询「什么时候发货」仍能命中，就把 STALE 写成已人工验证。那只证明 **回退后查询还可用**。回退到仍含该话术的版本时，重新搜索命中是预期现象， **不能** 证明旧候选已失效。

STALE 要看的是：**已经拿到的那条旧候选** 在回退后不得再被当成有效稿复制。产品文案是 `内容已变化，请重新查询`（错误码 `STALE`）。发布被替换时，Query 也可能先出现 `当前版本已失效，请重新核验`。

人工步骤：

1. 登录，平台「千牛」，商品范围全店，查询「什么时候发货」，复制一条候选（只进剪贴板）。 **不要关掉这条结果。**
2. 用合成 Owner 在 loopback 上对当前发布做一次回退（`POST /v1/content/rollback`）。本清单不实现回退，也不依赖未合并的 M3 #71 脚本。没有安全的合成 Owner 回退入口时，本项记 **未观察**。
3. 回到 **同一条旧结果**：再点复制。必须失败，提示内容已变化 / 当前版本已失效，而不是再次「已复制」。
4. 允许重新查询。重新搜「什么时候发货」 **仍可能命中**——把这一步单独记「回退后仍可查询」， **禁止** 用来勾选 STALE。
5. 禁止用 `backend-runtime.e2e.test.ts`、Playwright 或任何 adapter 复制 STALE 断言代替本项。

勾选：

- [ ] 回退后，旧候选再复制被拒绝（STALE / 版本已失效）
- [ ] 没有仅仅因为同一句发货话术还能搜到就勾选 STALE
- [ ] 未把 D5 / M3 自动化当成 Mac 人工 STALE 通过

## 6. 若本次打开的是 M4 未签名包

仅当真人双击/打开了 M4 产出的本机未签名 macOS 应用时填写。本页 **不授权** 执行 `pnpm package:mac:local` 或 `pnpm package:mac`，不签名、不公证、不外发。未打开该包则整节记 **未观察**。

期望（观察，不是再打一次包）：

| 项 | 通过标准 | 不能当成 |
| --- | --- | --- |
| 产物身份 | 文件名含 `UNSIGNED`；来自 `release/local-unsigned/` 一类本机证明目录 | 正式外发包、已签名、已公证 |
| 配置 | `~/Library/Application Support/客服话术浮窗 Demo/synthetic-stack.json` 存在，且由合成栈写入 | 打包态读环境变量 |
| 文件内容 | `mode` 为 `synthetic-local`；`apiOrigin` / `identityOrigin` 都是精确 `http://127.0.0.1:<端口>` | 飞书、非 loopback、带路径/账号的 URL |
| 启动 | 栈已 `start` 的前提下，未签名 `.app` 能走第 2～4 节主链 | Gatekeeper 对外部下载放行、可发给别人 |
| 环境变量 | 打包态即使误设 `CUSTOMER_AGENT_DESKTOP_*` 也必须忽略 | 用开发态 env 冒充打包路径已验 |

`codesign --verify` 对本机 UNSIGNED 包预期失败，只能证明未签名，不能证明 M5 通过。

勾选：

- [ ] 本次确实打开了 M4 未签名 `.app`（否则记未观察）
- [ ] userData 中的 `synthetic-stack.json` 被该包使用，而不是环境变量
- [ ] 未把未签名包写成已签名或可外发
- [ ] 未在本任务里重新打包、签名或公证
