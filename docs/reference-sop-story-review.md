# SOP 候选故事结构检查

此工具检查业务审阅用的候选路径。它不读取工作簿，也不生成正式 graph、维护稿或发布请求。真实来源的只读盘查和候选文件保存在仓外；仓内测试只使用合成内容。

## 运行与结果

在仓库根目录使用 Node.js 24 和现有依赖运行：

```sh
node scripts/check-sop-story.mjs /绝对路径/候选.json /绝对路径/新报告.json
node --test scripts/check-sop-story.test.mjs
```

报告路径可省略，省略时输出到标准输出。输出文件使用独占创建，不覆盖已有文件或输入文件。检查器只接受 JSON，不接受 XLSX。输入上限 4 MiB；每份输入最多 64 个流程，每个流程最多 128 个节点、512 条边、64 个故事，每个故事最多 512 条边。

| 退出码 | 状态 | 含义 |
| --- | --- | --- |
| 0 | `review-structure-complete` | 此输入的结构检查通过，不代表业务正确或获准发布 |
| 3 | `needs-business-confirmation` | 结构没有发现错误，但含建议节点、建议边或未决边 |
| 2 | `invalid` | 输入、图结构、故事路径或文件读写有误 |

所有结果固定 `publishable:false`、`runtimeEnabled:false`。源码和数据形状由 [check-sop-story.mjs](../scripts/check-sop-story.mjs) 拥有，行为验证由 [check-sop-story.test.mjs](../scripts/check-sop-story.test.mjs) 拥有。测试已纳入 `pnpm test:workflow`。

## 数据含义

根对象用 `schema` 明确 v1 或 v2 版本，包含来源摘要、工作表名、行数及流程。每个流程明确起点、节点、边和故事。字段严格匹配，禁止额外字段被静默丢弃。

- 节点区分动作、判断、等待、终点和参考资料。参考资料不能作为起点或参与执行边。`support` 区分来自原表和人工建议；来自原表的节点必须有非空来源行。
- 边区分原表支持的局部关系 `explicit`、建议关系 `proposed` 和目标未知的 `pending`。前两种必须有合法目标；后一种不能携带目标。`explicit` 必须有非空来源行。
- `conditionKey` 是待审核条件的标识，不是条件表达式。不同标识不能证明条件互斥或覆盖全部情况。
- 故事由具体边 ID 组成，从流程起点逐边走到终点、等待或未决出口。遇到未决出口必须停止。等待不算完成。
- 原表位置只用于追溯，不能代替稳定业务身份。候选语义 ID 也不等于已批准的正式编号。

`terminal` 只表示这条故事不再继续，不能单独用于判断问题解决或统计业务完成。当前过敏候选分别表达补偿履行并告知后完成、说明完成且没有待处理事项，以及坐席停止跟进。三者含义不同；完成说明不表示已发补偿或症状消失，停止跟进不表示问题解决。结束原因由候选规则与专项验证区分，结构检查器不执行该业务判断。

检查器分别统计仅使用明确边、以及加入建议边后的可达节点。加入建议边后可达不能写成业务已确认连通。它还检查引用、重复身份、不可达节点、隐含动作分流、无出口区域以及故事结局不符。

等待节点可恢复，允许存在能到等待或其他出口的环。这个检查不证明每条路径必然终止，也不证明等待一定能得到外部结果。

## 多选状态版本

`sop-story-review-v1` 只检查路径结构。`sop-story-review-v2` 在每个流程中增加 `selections` 数组，显式声明需要跟踪的选择组。两种版本分开识别，不能用旧版本的结构通过代替多选状态检查。

每组声明 `id`、`selectEdgeIds`、`finishEdgeId`、`confirmEdgeId`、`resetEdgeIds`、`minSelected`。每条故事从空集合开始，选择边把对应 ID 加入集合，重复选择不增加数量，重置边清空集合。完成和确认边均检查最少选择数量。缺少被引用的边或混用不同状态操作会被拒绝。选择规则无效时，该流程的故事标为 `invalid / unchecked`，不再执行状态模拟；单条故事首次发生空选错误即停止，避免重复诊断放大。

报告的 `selectionChecksApplied` 表示是否应用 v2 语义；使用方还需核对覆盖组是否完整、故事是否实际执行且通过，不能仅靠这个标记声称已检查全部业务。当前过敏候选要求覆盖轻微五项和明显不适四项两组，均不包含无回复兜底。

适用性和文字间是否矛盾不由集合数量判断。选择数量通过不等于内容正确，复制或发送仍属于后续正式执行链的独立行为。

## 证据边界

来源摘要只检查格式，来源行只检查合法范围。核验人必须另行核对实际文件的 SHA-256、表头、行号及内容语义；不能只改候选 JSON 的摘要就声称来源已验证。

结构就绪不等于合同接收、真实数据审核、权限可用或正式发布。旧六表的来源绑定和正式候选门禁保持独立。对应门禁的有界代码验证见 [verify-sop-release-gate](../.agents/skills/verify-sop-release-gate/SKILL.md)。
