# 检索基线报告（2026-10-24）

E1 的产出：把「检索好不好」变成可复现的数字。报告只跑当前桌面检索链路，不改链路。

## 测的是什么

`apps/desktop/src/shared/hybrid-retrieve.ts` 的 BM25 + RRF 融合，加 `retrieval-quality.ts` 的弃答门。参数是仓内现有值：字段权重 title 3 / question 2.5 / answer 1，BM25 `k1=1.2 b=0.75`，RRF `k=60`，池 24，只取前 3。

## 没测什么

- **向量与重排两档没跑。** 它们要 MiniMax 凭据；没有凭据时 `rankScripts` 的第二路回落到答案文本 BM25，本报告量的就是这条回落路径。所以这不是「BM25 + 向量 + 重排」的上限，是它的下界。
- **不是生产话术库。** 生产索引在仓外（`retrieval-index.json`），见 `docs/how-to-verify-desktop.md`。本报告用的是本仓编写的合成语料。
- **排序不看平台。** 评测对全库排序，再按金标话术的平台把正例分开计。千牛和抖音是两套题，数字不必相同。负例的平台是 `any`，不进这两行。

## 语料与题集

| 项 | 数量 | 位置 |
| --- | --- | --- |
| 合成话术 | 62 条（售前 20、活动 10、售后 16、产品 16） | `apps/desktop/tests/fixtures/retrieval-eval/corpus.json` |

| 负例查询 | 50 条（话题在语料中不存在） | 同上 |

分层：`dev` 160 条（28 条话术的正例 + 20 条负例），`held-out` 200 条（34 条话术的正例 + 30 条负例）。

划分按 `sha256(scriptId)` 取模 5，小于 2 进 dev。**划分是话术的属性，不是查询的属性**：同一条话术的正例不会跨两侧，否则「改一版再看 dev」就等于看了测试集。

正例不与 `title` / `questionText` 逐字相同，测试里有一条断言专门守这件事。否则查询等于索引字段，数字会假性接近 100%。

## 三个结论

### 1. 弃答门几乎不起作用

50 条负例只有 15 条被正确拒绝（dev 5/20 = 25%、held-out 10/30 = 33.3%）。也就是说，问一条语料里根本没有答案的问题，三分之二的概率会拿到一个看起来像答案的候选。

机制在 `apps/desktop/src/shared/retrieval-quality.ts`：`MIN_QUERY_BIGRAM_HITS = 1`，只要**一个**长度 ≥2 的二元组出现在标题或问句里就放行；`STOP_BIGRAMS` 没有收录「多少」「需要」「不会」「多久」这类通用词。

实测误放行的例子（负例 → 被命中的话术）：

| 负例 | 命中 | 命中的二元组 |
| --- | --- | --- |
| 加盟费多少钱，怎么代理你们品牌 | `syn-product-002` 功率是多少瓦 | `多少` |
| 我想开一家门店，需要什么条件 | `syn-presale-016` 需要自己安装吗 | `需要` |
| 有没有招商加盟的政策说明 | `syn-presale-004` 洗涤后会不会缩水 | `不会` |
| 保险理赔需要哪些材料 | `syn-product-001` 具体参数在哪里看 | `多少` |

这条是 E1 最有价值的发现：它说明「没有命中就升级」这个产品承诺，现在依赖的是一个一元的判断。

### 2. 45 条正例连一个候选都拿不到

360 条里有 45 条（12.5%）经过弃答门之后是空列表。这类失败和「排错位置」不同：坐席看到的会是「没有命中」，而不是一个错答案。空结果集中在产品类（参数、噪音、配件、支付），因为这类问句的词汇和标题几乎不共享二元组。

### 3. 产品类明显弱于另外三类

held-out 里产品类 Top-3 51.4%、MRR 0.486，另外三类都在 71% 以上。产品类的话术标题偏「说明书式」（`功率是多少瓦`），顾客问法偏「场景式」（`一小时耗几度电`），二元组重合最少。这与结论 2 是同一个原因。

## 怎么复现

```bash
pnpm --filter @customer-agent/desktop eval:retrieval
```

输出分 `development` 与 `held-out` 两段，每段一张按类目和平台分组的表，后面列出未命中明细。测试里带了回归下限：held-out 正例 ≥150、负例 ≥25、Top-3 >60%、无命中 >25%。**下限不是目标**，它只保证改动后数字不会在无人察觉的情况下崩掉；提高下限属于改链路的那张卡。

## 下一步（不在 E1 范围）

- 弃答门收紧是独立改动，应当先在 dev 上试、再看 held-out，一次只看一次。
- 向量与重排两档需要凭据才能量；有凭据后同一套命令直接给出对比。
- 生产语料上跑同一个脚本时，报告输出留在仓外（索引本身也不在仓内）。
