# 真实六表业务身份候选设计

状态：候选设计，不是业务批准，也不进入正式 graph。机器可读登记见 [真实六表候选登记](./sop-real-six-sheet-candidate-registry.json)，所有条目的 `enabled` 都是 `false`。

本文只根据六张工作表名称和现有系统的编号约束设计命名方式。它不读取工作表正文，不把物理行号、图片顺序或合成 fixture 当成业务语义。

## 编号规则

稳定业务编号使用 ASCII 字符，并以 `menokin.` 开头。编号一旦进入正式发布目录就不再复用。工作表改名、排版调整或插入行不会改变编号。废弃内容保留原编号，并通过新版本和状态记录停用。

候选编号只表达业务对象的类别和名称。它们不是行号，也不是正式触发词。

表中的入口词只是待审核候选。它们在业务确认前不能进入 Query 召回或自动打开 SOP。尤其是“售后”“税收”这类宽泛词，必须先补充排除词和适用范围。

## 编号层级

正式 graph 使用四类编号。每一层只拥有自己的业务身份，避免把工作表、任务和资源混成一类。

| 层级 | 形式 | 用途 |
| --- | --- | --- |
| 家族 | `menokin.sop.<family>` | 表示一个可被坐席选择的 SOP 家族。 |
| 流程 | `menokin.sop.<family>.flow.<business-slug>` | 表示一个独立的业务结果或结束条件。 |
| 任务 | `menokin.sop.<family>.task.<business-slug>` | 表示流程内的确认、判断、话术或结束节点。 |
| 资源 | `menokin.resource.<family>.<business-slug>` | 表示可被流程引用的资源，不自动成为流程节点。 |

过敏流程目前只有家族级机器候选登记，尚未正式冻结。[过敏流程映射审阅卡](./reviews/2026-10-31-sop-allergy-mapping-review.md)另列任务和分支的命名候选，仅供审阅，不进入正式映射。业务没有提供稳定名称和证据前，系统不得用行号、标题截断或图片序号补出正式子编号。

六张表的候选身份和入口词只登记在 [机器可读候选登记](./sop-real-six-sheet-candidate-registry.json) 中。该 JSON 是候选登记的唯一写入来源。本文只解释编号规则和运行边界，不复制候选值。

## 入口词的正式形状

每个业务身份最终需要一组经过业务确认的入口声明。每条声明至少包含以下信息：

- 坐席实际会识别的词或短语。
- 该词允许进入的业务身份。
- 容易误匹配的排除词。
- 适用品牌、商品、店铺或场景。
- 业务确认人和确认时间。

同一个入口词可以对应多个候选，但 Query 不能因此自动启动流程。它应展示候选身份，让坐席明确选择 SOP 或普通话术。规则集和资源集只能作为检索结果出现，不能伪装成 SOP。

## 过敏流程的当前建议

保留家族级候选 `menokin.sop.allergy`。它包含一个坐席判断入口和多个步骤分支。目标步骤使用任务编号，例如 `menokin.sop.allergy.task.<business-slug>`。审阅卡中的候选名称仍需业务确认，不能直接生成正式任务。

当前已确认的业务约束是：坐席直接判断，不转人工；信息不足时使用流程内的补充确认步骤。具体判断条件、分支目标、入口词和适用范围仍需绑定到工作表的业务行区段。

## 业务确认顺序

1. 确认每个候选身份的正式名称和稳定编号。
2. 确认入口词、排除词和适用范围。
3. 确认流程分支和结束条件。
4. 确认知识、资源和图片的所有者与可见对象。
5. 确认生效时间和失效时间。

在第五步完成前，映射保持 `needs-business-confirmation`，不生成正式 graph snapshot。
