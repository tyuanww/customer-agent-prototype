# 如何核对职位名单查询权

登录成功之后，看顶栏能不能查询。看到「没有权限，请找人开通。」只说明这次没有查询权。查询按钮还在，不表示服务端已经放行。

字段和状态见[职位名单权限模型](reference-job-roster-permission-model.md)。

## 前提

- API 以飞书登录启动，并且接上了业务库。没有业务库时，接口可以返回 `unknown`，那不是数据库放行。
- 空库第一次登记时，`ROSTER_TENANT_ID` 和 `ROSTER_APP_ID` 要成对设置。只设一个，或和库里已有的唯一一对对不上，登录投影会跳过。

## 步骤

1. 看桌面顶栏。出现那句固定句子时，`permission_state` 不是 `ready`。没有这句句子，并且状态是 `ready`，才表示当前店铺集里至少有一家店的查询截止时间还在。

2. 读 `GET /v1/auth/job`。两边都没有职务时返回 404，正文是「职务未识别」。有正文时只含 `title`、`directory`、`permission_state`、`message` 四个字段。多出来的字段，桌面主进程会拒绝。

3. 按状态往下看，不要用按钮可见性代替这一步。

   - `pending`：人已经登记，当前店铺集里还没有可查询的系统授权。
   - `denied`：缺部门、职务编号对不上目录，或有业务库但没有读到库存状态。
   - `expired`：事实窗口已经过去，或系统查询授权过了 `expires_at`。
   - `revoked`：事实未启用，或系统查询授权已经撤销。
   - `ready`：`message` 为 `null`。其它状态的 `message` 必须一字不差地等于「没有权限，请找人开通。」。

4. 发布、导入和授权不会因为这次登录自动出现。要开通查询，走已有的显式签发，不要在登录路径补 `publish`、`import` 或 `grant`。

## 怎样确认

- `ready` 的响应没有那句句子。其它五种状态都有，而且不能改字。
- 未知职务编号不会被当成标题。标题来自目录或本次登录快照。
- 人工查询授权还在。登录撤权只动签发人是 `query-signer`、原因是「职位名单系统签发。」的系统查询授权。

## 失败时

- 404「职务未识别」：数据库没有这个人的职务，本次登录快照里也没有。先确认飞书职务原文能对上目录，而不是改接口去猜一个标题。
- 投影被跳过：检查两个环境变量是否成对，以及库里是不是有多对 tenant/app。
- 改签发函数时只改 `0049_roster_lifecycle`。`0047` 和 `0048` 是已经应用过的历史正文。
