# Menokin 首批资料整理对照

## 已确定的输入

Menokin 是首批店铺；业务在飞书表格维护，日常导出规范 CSV。首期授予总监和经理，不改变总监/经理/主管/组长的既有业务能力上限。首批 FAQ 已选 B（`SRC-LOCAL-04`），不是重新从 A/B 中选择；`SRC-LOCAL-04` 是资料盘点代号，不是可直接写入正式 `sourceId` 的来源登记。

FAQ 是文件格式，内容仍进入既有产品、活动、售前、售后四个域，没有第五个 FAQ 库。下表只引用计划中已有表头/结构盘点；行数及媒体数不能证明内容完整或可发布。

| 既有来源 | 已知结构 | 对应整理方式 |
| --- | --- | --- |
| B / SRC-LOCAL-04，首批 FAQ | A 列无表头；B/C 为快捷短语/产品话术 | B → 标题，C → 标准话术；A 列等业务确认，不猜作商品或分类 |
| SRC-LOCAL-02 / 售前 | 快捷短语、产品话术 | 同样映射标题/标准话术，登记域为 presale |
| SRC-LOCAL-03 / 售后 | 快捷短语、产品话术 | 同样映射，登记域为 aftersale；内部处理说明与对客正文需要业务区分 |
| SRC-LOCAL-05 / 活动 | 快捷短语、产品话术 | 同样映射，登记域为 campaign；每条活动必须补真实失效时间 |
| A / SRC-LOCAL-01，备选 QA | 分类、产品、业务填写问题、话术 | 暂不并入首批；若以后获准，分类/问题/话术分别对应分类/标题/标准话术，产品名称先核对登记编号 |

B 的包内媒体为 1 个，售前 3 个、售后 2 个、活动 1 个。本期是纯文字入口，不能只因 CSV 不含图片就认定图片无业务含义；业务须确认必要性并把必要内容整理成完整文字。系统不从图片猜答案。

## 23 列规范的准确对照

固定顺序来自 [`CSV_HEADERS`](../packages/content-intake/src/policy.ts)，解析和业务规则由 [`csv.ts`](../packages/content-intake/src/csv.ts) 与 [`faq-rules.ts`](../packages/content-intake/src/faq-rules.ts)拥有；本表不新增列或永久原表映射。

| CSV 列 | 规范字段 | 从哪里来 / 本次能确认什么 |
| --- | --- | --- |
| A | sourceId | 从已登记来源预填；不能使用本地盘点代号或合成示例 ID 代替 |
| B | templateVersion | 固定 `faq-csv-v1`，不是原表的 B 列 |
| C | brandId | 从登记品牌预填；显示名 Menokin 不自动等于登记 ID |
| D | scope | 从已登记店铺或品牌范围预填；是否为品牌/店铺另由可信上下文提供 |
| E | domain | 登记域 `product` / `campaign` / `presale` / `aftersale`；每份来源对应一个域 |
| F | 条目编号 | 沿已确认的一次性清洗/编号回写约定填写；稳定、不复用，不按每次上传重编号 |
| G | 标题 | B 及三域原表“快捷短语”；保留原含义，不强制改成问号结尾 |
| H | 标准话术 | 原表“产品话术”；多行、逗号、引号保留；业务先区分内部说明 |
| I | 商品编号 | 只填已登记商品引用；原产品名称不能直接当 ID，不明时等业务确认适用范围 |
| J | 场景编号 | 只填已登记场景引用；是否通用由业务确认，不依据模糊文字自动分配 |
| K | 分类 | 使用业务确认分类；B 的 A 列不能默认映射到这里 |
| L | 适用说明 | 业务确认的适用条件文字；不授予权限，也不能代替 I/J 的登记引用 |
| M | 状态 | 明确 `启用` 或 `停用`；删除文件中的行不会自动下架 |
| N | 生效时间 | 真实带时区的 ISO 时间（适用时）；不把文件修改时间当生效时间 |
| O | 失效时间 | 活动必填，须晚于生效时间；不得按示例日期推定实际活动期限 |
| P | 对应通用条目 | 仅店铺覆盖时填已确认 `sourceId/businessEntryId`；不能按文字相似度自动关联 |
| Q | 内部说明 | 只给维护人员的说明，与对客正文分开；不得将此列拼入复制答案 |
| R | 风险提示 | 业务确认的风险说明；不降低既有结构风险判断 |
| S | 附件说明 | 非空会得到 `UNRESOLVED_MEDIA` 并阻断；先解决必要内容，不能删掉提示冒充图片已经处理 |
| T | 品牌不可覆盖 | 空/`false`/`true`；仅品牌通用来源可设 `true`，店铺源不能藉此扩权 |
| U | 问法编号 | 额外问法的稳定独立编号；全文件唯一，关联 F 列条目 |
| V | 问法 | 有额外问法才填写；不默认把快捷短语再复制成独立问法 |
| W | 问法状态 | 有额外问法时填 `启用` / `停用`；没有额外问法时 U/V/W 同时为空 |

同条目存在多个独立问法时，重复完全相同的 F～T 字段，每行 U～W 表示一条问法；F～T 任一不一致都整批拒绝。A～E 每行都必须匹配服务端登记，文件不能改变授权范围。CSV 报告使用逻辑记录号：表头是 1，第一条数据是 2，正文换行不增加记录号。

## 复用入口及已验证范例

现有工具已具备标准模板生成、两格式解析、隔离子进程及错误报告，没有必要新增 parser、任意映射 UI 或永久原表兼容分支。这里的归一化是“规范文件 → 规范 FAQ/问法行”；它不会自动补齐 B 原表的业务语义或真实编号。

| 需要做什么 | 现有入口 |
| --- | --- |
| 查看可解析的 23 列文件 | [原字节合成模板](../packages/content-intake/experiments/csv/synthetic-template.csv)，2 条 FAQ、2 条独立问法；仅合成 source/brand/shop，不用于真实上传 |
| 从已登记上下文生成空模板/示例 | `@customer-agent/content-intake` 的 `createCsvTemplate(context, records)`；技术调用，无自动登记或授权副作用 |
| 隔离解析原字节 | `@customer-agent/content-intake/runner` 的 `createParseRunner().parse(bytes, context)`；失败返回空 rows/questions |
| 保存并重开可读错误报告 | 同包 `writeIssueReport(issues)`；生成真实 XLSX，只有坐标、错误码与修正说明，不复制源正文 |
| 规范文件进入现有产品流程 | [开发指南](how-to-develop-content-intake.md#p2-faq-原生上传)：选择有权来源→文件→参与人声明→检查→来源/质量核对→确认发布；本次不启用真实来源 |

本轮将既有模板和新生成的四域纯合成文件落盘后，交给现有独立 parser 实际消费：四域均保留多行、逗号、引号、BOM、稳定条目/问法编号及显式停用。四个无效文件分别验证活动缺期限、缺正文、未解决必要图片和来源错配；均整批拒绝，XLSX 错误报告重新打开后坐标/修正文字一致，未含源正文。共 9 项产物检查通过；详细产物位置、摘要、命令和第一次探针断言修正见[本轮核验记录](../evidence/qa/intake-menokin-readiness/checks.json)。这些小型合成产物留在本轮隔离工作区，不复制进正式资料目录。

原 97 项 CSV/XLSX 解析及 runner 验证复用[既有证据](../evidence/qa/intake-csv-runtime/README.md)：`packages/content-intake` 整树及锁文件相对原完成提交未变，记录中的相关输入摘要重新核对相符；本轮未重复全量测试。新 probe 只核验交付产物，不将其写成数据库、UI、真实资料或安装验收。

## 真实整理前只缺这些内容

1. **原表语义与媒体：** B 的无表头 A 列具体用途；必要图片中的业务文字，以及售后哪些段落属于内部说明。不能在缺少回答时把未知列/图片静默丢掉。
2. **真实登记绑定：** 唯一权威飞书来源及其当前版次、对应的实际来源/品牌/店铺登记；由哪位具名总监或经理负责确认，哪些实际人员参与改稿。岗位名不能替代 principal，凭据不放聊天或资料表。
3. **适用条件：** 商品/场景使用现有登记编号；对没有限定的条目，由业务明确确认“通用”，不推断空值含义。活动逐条确认真实生效/失效时间。
4. **历史关系：** 已有发布目录与新来源的认领对应及稳定编号回写结果。复用已确认的历史清洗成果，不从较早原始文件覆盖现行版本；保留期限继续由既有容量事项决定，本文不设值。

以上到位且真实整理/接入获准后，再在受控环境按表转换、人工核对、写回稳定编号并重新导出，使用同一 parser 试运行并保存完整报告。解析通过之后仍需来源、质量、发布权限和二次确认；真实资料正文不进入仓库、测试 fixture 或外部模型。当前没有执行真实转换、写回、导入、认领、飞书访问或运行激活。
