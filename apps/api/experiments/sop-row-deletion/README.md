# SOP 单行删除后继消费者实验

应用消费者仍是实验，未注册 HTTP，不进入生产 API 构建。治理后继已由379b793冻结并导出，产品正式接收OpenAPI1.24.0/schema1.28/0040；数据库测试直接消费已核验的产品迁移，不再读取仓外候选SQL，不建立跨仓运行时依赖。

`consumer.ts` 复用现有 product session、当前资格、candidate key、事务截止和永久回执。默认要求真实产品会话；测试显式关闭会话要求、只用合成人员 DTO，仍执行业务资格检查。函数返回新版 `IntakeCandidate`；最后一行返回取消后的原候选。预览副作用只在确认提交或成功回执重放后发生。私有回执保留该版本完整剩余行集合及冻结材料的输入对象 ID；预览所有者按单调版本投影，即使没有图片也保留版本屏障。删除从准确输入对象的暂存图片生成独立候选数组，解析结果晚到时既不能恢复已删图，也不会丢失未删图；旧回执不影响重导/发布后的新版本，后续成功操作也能纠正前次未知提交尚未投影的删除。输入字节不在缓存时失败关闭，不借用其他代际图片。这是显式实验消费者的私有回执；合同已接收，生产HTTP返回适配仍未启用。

映射由 `tryParseSopAsFaq.rowBindings` 产生；治理函数验证它与完整候选正文/标题对应。正式 runner 接入必须在冻结同一事务登记，无完整映射的旧候选不能猜测处理。本实验不会给旧媒体删除函数补权限，不改已消费 DELETE/204 wire。

## 可信冻结入口候选

`trusted-stage.ts` 从已采用的输入对象读取字节并核对大小与 SHA，调用现有 SOP parser 和 `materialFromParse`。当前业务池复用只读上下文、四个用途受限的媒体预约/登记/释放函数、`read_sop_inherited_assets` 和窄 `freeze_sop_parsed_candidate`：后者在同一事务中核验 job／actor／source／object／base／prior、写候选、完整行映射及媒体、推进 job。没有授予登录角色候选表或媒体表的广泛 DML，不复制生产 runner 状态机，也不改生产 `freezeParsed`。

当前 parser 行通过 `freshRowIds` 明示；文字相同仍可替换或移除图片。内容版本沿唯一 SOP parser 透传：工作簿版本列优先，无版本列时使用文件 SHA；新 operation／job 不代表新内容版本。删除事件永久保留来源、内容版本、行、操作者和图片删除快照。同来源同内容版本不得恢复已删行（包括纯文字行），更换字节但保持相同声明版本也不能绕过。新内容版本仅在图片从未采用、无候选和发布引用、来源及元数据相符时可重新暂存；当前生命周期状态恢复，旧删除事件和时间不变。遗漏行只接受同来源、同发布谱系、完整正文相等且有确证行映射的继承；映射缺失或歧义拒绝，不按序号猜。继承图片从精确发布谱系取得私有 payload 描述符，逐张读取持久字节并校验大小、SHA 和图片类型；不依赖预览 Map 命中。重复已完成 job 仍重新解析原文件、检查完整冻结材料与资产摘要，只复用该 job 精确结果中的 canonical payload；不重复预约，也不以历史结果读取绕过失效状态或已删行屏障。已 validated 的恢复还读取该 job／actor／source 自己未采用的预约描述符；只有冻结确认成功或明确回滚后，才经原带文件锁和 SQL 引用保护的释放能力清理冗余副本，未知提交仍保留。继承与已冻结图片的字节读取在内容锁之外；最终短事务重读并比对完整行／媒体快照及当前资格，变化时拒绝，不把读取前的资格缓存成放行依据。文件里的行重排可能改变既有序号 ID，此时确证映射不匹配会拒绝，候选没有自动迁移旧 ID。

预览输入在确认资产 SQL 成功后、COMMIT 前暂存；确认提交后才投影候选别名。这样删除在提交后先返回，也能保留未删除图片。每次暂存由预览所有者返回独立 commit/rollback 句柄。确认成功只采用自身快照并清理其前驱；明确回滚标记该代失效，恢复时跳过已回滚前驱，身份守卫保护并发后继暂存和独立别名；未知提交不结算、保留以便重试。同版本删除回执只能收缩当前投影，末行取消后的旧回执不能从输入恢复图片。SQL 不能证明工作簿解析正确，可信 parser 进程仍是边界；该入口没有接受 renderer 传入的任意材料。

## 持久附件边界与验证

`media-lifecycle.ts` 拥有业务预约、持久登记与明确失败后的清理顺序；`content-object-store.ts` 拥有本机附件文件、私有目录与同 objectId 文件锁。锁覆盖文件 I/O 结束与数据库登记/释放结束，数据库断开不释放仍活跃 writer 的文件锁。另一实例遇到 BUSY 明确拒绝，可重试原 job；未知提交保留原预约，不按时间猜测可删。崩溃残锁没有自动过期/抢锁恢复，本候选不宣称生产对象存储或崩溃自动修复。

`persistent-media.ts` 只作为显式候选 reader 注入既有 usage。SQL 依据当前操作者、会话及租约定位精确发布；usage 仍执行原范围、条件和有效期过滤，随后按可见对象去重。列表只读描述符，打开一张图时才读取并验证该张图片；私有 payloadObjectId 不进入公开 HTTP 返回。字节读取不持有数据库事务或全局内容锁；返回前重新执行同一会话、租约、范围和可见行选择，核对图片身份／摘要／类型／大小，且沿用首次授权最早截止。读取期间撤权或到期不返回字节。默认服务未自动切换该 reader。

旧发布入口的图片继承测试也直接使用0040内的后继发布器，不再要求仓外目录或额外候选开关。测试用真实旧归一化/质量函数准备合成售前资料，在 `app_content_admin` 下发布；检查两行同图、精确谱系、采用时间和冷读字节。缺可靠行映射时整笔回滚；数据库触发器不能检查物理磁盘文件，缺文件由冷 reader 拒绝。

继承校验按唯一候选版本一次展开完整条目，保留来源、基线、行/业务 ID 与完整 JSON 相等条件。实际五代合成发布累计500条共享小图关系、501条拒绝，并验证继承文件读取并发峰值为1；不代表500张最大图片或RSS压力验收。升级测试中用途×MIME/大小的独立CHECK层探针仅在一次性事务内隔离输入格式触发器；正常CSV/XLSX输入格式另用完整触发器验证，不作为生产旁路。
